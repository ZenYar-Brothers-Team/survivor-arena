# Ручные плейтесты

Основание: [DECISION-0024](../decisions/0024-playtest-records-in-git.md), принято пользователем 2026-09-21.

Долговременные отзывы и выбранные отчёты хранятся здесь в Git. Runtime продолжает экспортировать в AppData; перенос выполняется после прогона пользователем или AI при обработке отзыва. Автоматической записи в репозиторий и автоматического commit нет.

## Запись прогона

Один Markdown-файл на прогон: `YYYY-MM-DD_<reportId-prefix>.md`, дата UTC из `createdUtc`, prefix — первые 8 символов reportId. При коллизии увеличить prefix. Полные reportId/runId обязательны. Использовать [шаблон](TEMPLATE.md).

Внутри каждого файла — отдельные нумерованные наблюдения OBS-01, OBS-02 и далее. Устойчивая ссылка на замечание: файл + номер; номера не переиспользовать. Повторное обращение к тому же reportId дополняет существующую запись. Новый прогон получает новый файл и ссылки на проверяемые замечания прошлого прогона.

После переноса этот Markdown — основная редактируемая запись отзыва. Новые заметки из локального feedback.md добавлять сюда с сохранением источника, не перезаписывая диагностику. Исходную цитату пользователя сохранять; неизвестные ожидания, время, причину остановки или условия помечать «не уточнено». Вывод AI отделять от наблюдения.

Состояние замечания: открыто → диагностировано → исправлено → проверено; также допустимы отложено и не воспроизведено с причиной. «Исправлено» требует ссылки на изменение, «проверено» — результата проверки/повторного прогона. Эти состояния относятся к замечаниям; execution status IP остаётся только в [STATUS](../implementation/STATUS.md).

## Артефакты

Для выбранного бага или сравнения сохранять `reports/<имя-записи>/run.json` без изменений и `feedback-original.md` как снимок исходного отзыва. В записи указывать относительные ссылки и SHA256 run.json. Summary можно получить из JSON; дублировать его необязательно. Массовые/промежуточные и synthetic exports не переносить автоматически. При отсутствии raw report явно указать ограничение; один путь AppData не обеспечивает доступность отчёта другим разработчикам.

При переносе проверить final/incomplete, совпадение report/run/config IDs, commit/dirty, hashes snapshots, quality/capabilities и связь marker с цитатой. Не заменять ранее сохранённый JSON другим snapshot молча; incomplete и последующий final хранить раздельно с явными ссылками, если нужны оба. Просмотреть notes и provenance на посторонние персональные данные перед добавлением в Git; не менять исходный JSON ради анонимизации без указания этого ограничения.

Запись отзыва не разрешает tuning. Анализ, предложения, approval и повторные сравнения выполняются по [BALANCE_WORKFLOW](../implementation/BALANCE_WORKFLOW.md); формат экспорта — [PLAYTEST_REPORT](../implementation/PLAYTEST_REPORT.md).
