# DECISION-0157 — FIELD-010: экранные события по расписанию с волной интенсивности

## Context

FIELD-010 «Чертог Спасения» — последнее поле линейки (после него полей нет). Карточка `Content_design.md` описывает геометрию общими словами
(«смешивает открытые арены, коридоры и плотные препятствия»), а ранее согласованный план геометрии
([proposal](../implementation/proposals/2026-10-01-field-geometry-variety.md), «Микрокатастрофы (010)») оставлял детали открытыми.
Пользователь в чате 2026-10-03 задал направление: события **без конкретного триггера и без объекта на карте**, которые просто начинаются в какой-то
момент, действуют по экрану и **бьют только игрока**; пример — широкая вертикальная красная полоса опасности, по которой затем сверху вниз
пролетает копьё. Набор из 13 вариантов предложен ИИ, пользователь одобрил его целиком («все, что ты предложил, нравится», «можешь все реализовывать»),
идею «кольцо с разрывом» отметил отдельно. Позже добавил: **интенсивность должна быть волнообразной** — то нарастать, то падать.
`Game_design.md` и `Content_design.md` без явного одобрения не меняются, поэтому правила фиксируются здесь.

## Decision

### Общие правила

1. **Событие без объекта на карте.** Его запускает только расписание (`ScreenEventRuntime`), а не предмет, зона или близость. События не имеют коллизии
   и не блокируют движение и атаки; опасность существует только пока горит красная зона.
2. **Только по игроку.** Враги, боссы, Путники и объекты событием не затрагиваются. Урон — **процент максимального здоровья** игрока
   (`damagePercent`), чтобы он имел смысл при любом билде.
3. **Каждая опасность бьёт не более одного раза.** После попадания опасность (hazard) больше не бьёт; урон наносится сразу (не «в секунду»).
4. **Телеграфия обязательна.** Любая опасность сначала красная зона (`telegraphSeconds`, нарастает по яркости), затем удар (`strike`). Раскладка
   фиксируется в мире в момент старта и не движется за камерой.
5. **Одно событие одновременно.** Пауза до следующего события отсчитывается от конца предыдущего.
6. **Безопасная область всегда есть и достижима.** При старте события сеточная симуляция (`ScreenEventSurvival`) проверяет, что игрок на **текущей** позиции,
   идущий со скоростью `fairnessSpeed` (по умолчанию 1,9 — ниже самого медленного персонажа 2,4), способен пройти все события без единого попадания. Иначе
   раскладка перебрасывается (до `fairnessAttempts`, 12); если честной раскладки нет, событие всё равно запускается и увеличивает `UnfairStartCount` (наблюдаемость;
   на текущем контенте ожидается 0, проверяется тестами). Размер раскладки задаётся в долях высоты экрана (`…H`), поэтому работает при любом разрешении.
7. **Боссы.** Пока жив босс или мини-босс (`suspendWhileBossAlive`), новые события не стартуют, а таймер ждёт; идущее событие доигрывает.
8. **Пауза.** Время событий идёт только в состоянии Running; в паузе ничего не продвигается и не рисуется заново.

### Волнообразная интенсивность

Интенсивность `I(t) ∈ [0,1]` — косинусная волна с периодом `wavePeriodSeconds` (150 с): `I = valley + (peak − valley) · (0,5 − 0,5·cos(2πt/период))`.
Забег начинается в «долине». Значения `valleyIntensity` и `peakIntensity` — ключевые точки этапов (`stages`, начало этапа в секундах Running), между этапами они плавно
интерполируются, поэтому пики растут по ходу забега без скачков. `I` управляет:
- **паузой между событиями:** `Lerp(pauseMax, pauseMin, I)` этапа, с разбросом ±15%;
- **выбором события:** вес записи пула = `weight · exp(−((intensity события − I) / intensityTolerance)²)`; событие, которое только что было, пропускается при наличии выбора;
- **редкими событиями:** стартуют только при `I ≥ rareMinIntensity` (0,8) и не чаще, чем раз в `rareMinIntervalSeconds` (150) от конца предыдущего редкого.

Стартовые значения: этапы с 0, 180, 360, 540 с; долина 0,05→0,20, пик 0,40→1,00; паузы 20–34 → 10–20 с; первое событие через 25 с.

### Поле

FIELD-010 стало играбельным как **открытая арена 160×160 без препятствий** (`interiorObstacleCount = 0`) с утверждённой землёй `FIELD-010-VISUAL-GROUND`; опасность создают события.
Волны, Путники и боссы временно общие с FIELD-001 по ссылке (как у FIELD-006/007/009), разблокировка — по существующему unlock FIELD-010 (DECISION-0125) и Dev-кнопке.
Финальные волны/боссы FIELD-010 остаются отдельной будущей работой.

### Авторские данные

Источник: `docs/balance/field010-screen-events-v1.json` → `scripts/content/fields.py` → `ProductionFieldEnvironmentPresentation.json` (ключ `screenEvents` презентации
`FIELD-010-PRESENTATION`). Схема: `Assets/Game/ScreenEvents/Json/*Data.cs`, проверка значений — `ScreenEventDefinition` / `ScreenEventsDefinition`
(обязательность чисел зависит от раскладки; висящее событие без этапа, этап без нередкого события, неизвестный id в пуле — ошибки загрузки).
Сид — `referenceSeed` для воспроизводимых запусков, свежий на каждый забег иначе.

## Consequences

- Код: новый модуль `Game.ScreenEvents` (чистый C#: `ScreenHazard`, `ScreenEventSpawner`, `ScreenEventSurvival`, `ScreenEventRuntime`, определения/DTO),
  `Game.Bootstrap` (`ScreenEventDriver`, `PlayerScreenEventTarget`, блок в `GameplayCompositionRoot`), `Game.Presentation` (`ScreenEvents` в определении окружения).
- Рисунок сейчас — placeholder-фигуры (красные полосы, светлая полоса-снаряд, дуга-кольцо, маска безопасного круга); арт заменит их по
  [брифу механик](../art/briefs/field010-screen-events-art-v1.md), логика не меняется.
- Предложение к `Content_design.md` (не внесено до одобрения): в карточке FIELD-010 заменить строку `Geometry / obstacles` на «Открытая арена без препятствий; опасность создают
  экранные события по расписанию (красная телеграфия, затем удар только по игроку, волна интенсивности; DECISION-0157)».
- Dev-вкладка **Events** (только Editor/Development Build, видна лишь на поле с событиями): кнопка на каждое из 13 событий запускает его через 2 секунды running-времени после нажатия (`ScreenEventRuntime.TryQueue`, расписание на это время стоит), плюс состояние: идущее/ожидающее событие, интенсивность волны, время до следующего, попадания, нечестные старты.
- Не реализовано: звук (предупреждение/удар), подсказка в HUD,
  финальные волны и босс-привязка FIELD-010, учёт препятствий (их на поле нет), баланс урона и пауз по плейтесту.
- Поведение в игре визуально проверено только на кадрах PlayMode (placeholder); стартовые числа — не финальный баланс.

## Approval

Правила событий (без триггера, только по игроку, красная телеграфия, пример с копьём), набор из 13 событий и тема «кольцо с разрывом» утверждены пользователем в чате 2026-10-03; требование
волнообразной интенсивности — там же. Числа (урон, тайминги, этапы, веса, `fairness*`) — стартовые точки ИИ для плейтеста. Правка карточки FIELD-010 в `Content_design.md` ждёт отдельного одобрения.
