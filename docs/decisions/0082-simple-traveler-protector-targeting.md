# DECISION-0082 — Простой выбор цели движения Путника-защитника

Status: Approved (прямое поручение пользователя 2026-09-28)
Date: 2026-09-28
Related IP: IP-30, IP-27, F1-09
Related content IDs: TRAVELER-005, TRAVELER-006, TRAVELER-009
Supersedes: DECISION-0035/0036 full reachable-component search/projection for Traveler placement and movement

## Контекст

Профиль точной F1-09 stress-сцены `250 ordinary + 2 bosses + 3 Travelers` показал, что главный поток
проводит около 8.0 из 15 секунд в дорогих вызовах `EnemyRuntime.FixedUpdate`; основная подтверждённая
причина — поиск Путником-защитником самой плотной группы обычных врагов. Реализация сравнивала каждую
пару обычных врагов на каждом physics tick, то есть имела стоимость `O(n²)`.

Пользователь явно разрешил предпочесть простой и достаточно адекватный алгоритм более сложному точному
поиску группы; сохранение прежней оптимальности поведения не является требованием.

## Решение

Путник-защитник находит четырёх ближайших живых обычных врагов того же забега, среди них выбирает
кандидата с наибольшим числом обычных врагов в `supportRadius` и старается занять позицию рядом с ним
со стороны игрока согласно существующему `guardOffset`. Цель пересчитывается раз в 10 секунд либо
немедленно после её смерти/исчезновения.

- Стоимость редкого выбора цели — `O(4n)`, то есть линейная, вместо `O(n²)` на каждом physics tick.
- При равной плотности выбирается кандидат, ближайший к игроку, затем применяется стабильный tie-break по `LifeId`.
- Support radius, aura/shield rules, lifetime, rewards и все численные параметры не меняются.
- Новая навигационная система, spatial hash или кэш групп не вводятся.
- Во время движения Путник не выполняет player-reachability/path search: player-only препятствия он проходит
  насквозь, как требует общий контракт поля. Движение лишь ограничивается внутренними границами арены.
  Проверка точки сохраняется только для первоначального spawn.
- Первоначальный spawn использует bounded rejection sampling: точка должна находиться внутри arena bounds и
  вне inflated obstacle rectangles. Полная связность с player spawn не вычисляется; геометрия поля не должна
  создавать изолированные свободные островки. Старые `IPickupPlacement`, `TryPlaceFrom`, BFS grid/cache и его
  reference implementation удалены как неиспользуемые production-механизмы.

## Приёмка

- Unit test подтверждает выбор самой плотной группы среди четырёх ближайших и немедленный retarget после потери цели.
- Отдельный test подтверждает игнорирование player-only obstacle при сохранении arena bounds.
- Тот же standalone stress benchmark обязан сохранить точный состав `250 + 2 + 3` и показать эффект
  на CPU/frame percentiles; density не снижается.
- Проверено 2026-09-28: targeted Pickup + Traveler 61/61 PASS; full project smoke 865/865 EditMode
  + 30/30 PlayMode PASS; exact stress p95 `16.673 ms`, p99 `16.680 ms`, max `37.367 ms` PASS.
