# DECISION-0132 — Тестовые поля (dev) и поле «Тест 02» с per-run кляксами

Дата: 2026-10-01. Статус: Approved по прямому поручению пользователя («сделай в игре ещё одну одиннадцатую карту… тестовая… всегда доступна… чисто для разработки», «всю процедуру генерации создай случайно, кляксы накидываются каждый раз заново»).

Related: [план разнообразия геометрии](../implementation/proposals/2026-10-01-field-geometry-variety.md), [DECISION-0003](0003-player-only-field-collision.md), [DECISION-0068](0068-per-run-obstacle-layouts.md).

## Граница

Добавляется одиннадцатое поле только для разработки, чтобы пробежать по геометрии кляксов до решения об их дизайне. Оно **не входит в десять designed fields** GDD/Content Design, не имеет карточки FIELD-NNN и не меняет их. Дизайн кляксов как production-геометрии (FIELD-002, 005, 007) остаётся Proposed в плане; это решение его не утверждает.

## Правила

- ID `FIELD-DEV-BLOBS`, окружение `FIELD-DEV-BLOBS-ENVIRONMENT`, presentation `FIELD-DEV-BLOBS-PRESENTATION`. Всегда доступно: unlock-условие `dev` (только `kind: field`, цена 0) — любой профиль видит его открытым, прогресс профиля не требуется, миграция сохранений не нужна.
- Спавн полностью как у FIELD-001: тот же timeline `FIELD-001-TIMELINE`, пул врагов, расписание Путников и боссы. Искусство и декор — FIELD-001.
- Арена 120×120 (поле `arenaSideLength` презентации); граничные стены сцены на время забега переставляются и возвращаются при `Shutdown()`; камера ограничивается этой же стороной.
- Препятствия: 20 кляксов, генерируются **заново при каждом запуске** (свежий seed; `referenceSeed` при `UseReferenceSeeds`). Три семейства: округлые (радиальные гармоники), угловатые (выпуклая оболочка, без «осколков» по `minAspect`), линейные (изогнутые сужающиеся полосы). Коллизия — полигон, только для игрока (DECISION-0003); картинка — плоская заливка с контуром, генерируется из тех же точек.
- Правила размещения: одна средняя клякса частично накрывает стартовый экран, но не ближе `playerClearRadius` (3.5) к игроку и её ограничивающий прямоугольник не накрывает спавн (spawn placement работает по AABB); остальные — вне круга `startClearRadius` (11), отступ от края 5, зазор между описанными окружностями не меньше 7; если набор не поместился, генерация повторяется с производным seed (до 8 раз), иначе ошибка.
- Все числа живут в `docs/balance/field-dev-blobs-v1.json`; Content Design и GDD не меняются.

## Последствия

- Dev-забеги на этом поле сохраняют результат как обычные: награда/прогресс по `FIELD-DEV-BLOBS` записываются в профиль и не влияют на разблокировки реальных полей (их условия ссылаются на FIELD-001…009).
- Коллекционный арт (`*-VISUAL-BACKGROUND`) для dev-поля не требуется; миниатюра — FIELD-001.
- Если кляксы будут утверждены как геометрия, их параметры переносятся в данные соответствующих полей, а это поле можно удалить без миграции.

## Dev-панель: вкладка Map

В development-панели (DEV, только Editor/Development Build) добавлена вкладка «Map» с кнопкой «Показать карту». Она включает угловой оверлей 440×440 (в рамках бюджета debug-поверхности): рамка всей арены, контуры всех препятствий, блокирующих игрока (полигоны кляксов, прямоугольники и круги других полей), и рамка текущего экрана камеры; юниты не показываются. Оверлей не перехватывает ввод и работает на любом поле. Данные берёт `FieldMapPreviewSource` из коллайдеров, созданных `FieldEnvironmentArtRuntime`; UI только читает (View → presenter → source).

## Соглашение о тестовых полях (для всех агентов)

Помимо десяти designed fields в игре может быть любое число **тестовых полей** для проверки геометрии и механик до их утверждения. Правила:

- **Условие unlock `dev`** в `Assets/Resources/Content/Meta/MetaEconomy.json` (`kind: field`, цена 0): поле всегда открыто на любом профиле; в магазин меты и в коллекционный арт (`*-VISUAL-BACKGROUND`) не попадает; сохранения не мигрируют.
- **Имя «Тест NN»**, где NN — номер designed field, геометрию которого поле проверяет (сейчас `FIELD-DEV-BLOBS` = «Тест 02»: кляксы для второй карты). ID вида `FIELD-DEV-<ИМЯ>`, чтобы не пересекаться с `FIELD-001…010`.
- **Порядок:** тестовые поля идут в `ProductionFields.json` и в экране выбора **строго после** FIELD-001…010 (генератор `scripts/content/fields.py` добавляет их в конец); проверяет `ProductionFieldDevBlobsContentTests`.
- **Экран выбора поля:** до 20 полей карточки занимают экран без прокрутки (картинки подгоняются под 4 ряда по 5); начиная с 21-го размер карточек не уменьшается, лишние ряды прокручиваются (`FieldSelectScreen.FittingRows`).
- Источник чисел каждого тестового поля — отдельный файл в `docs/balance/` (пример: `field-dev-blobs-v1.json`), выпуск через генератор; к дизайну (GDD/Content Design) они не относятся.
- Спавн тестового поля по умолчанию берётся у FIELD-001 (тот же timeline, пул врагов, боссы, Путники); отклонение описывается в файле поля.
