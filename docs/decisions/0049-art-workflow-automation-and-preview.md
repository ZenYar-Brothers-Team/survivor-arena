# DECISION-0049 — Подготовка арт-пакетов и короткие визуальные итерации

Status: Approved
Date: 2026-09-22
Related IP: IP-12A; implementation workflow

## Основание

После аудита времени и токенов пользователь поручил выполнить первые три предложения: единую подготовку утверждённого арта, быстрый визуальный цикл и единый запуск проверок. Это разрешение на инструменты и изменение workflow; оно не утверждает новые изображения или production content.

## Решение

Техническая подготовка явно утверждённых кандидатов выполняется пакетной командой с проверкой хеша, immutable versions, сохранением `.meta`, явными owner bindings и preflight перед записью. Скрипт может записать только этап `Prepared`; последующие gates требуют собственных доказательств.

Разрешено отложить затронутые EditMode tests до выбора визуального варианта при изменении существующих числовых полей четырёх presentation profiles, перечисленных в [инструкции](../../scripts/README.md#2-быстрая-визуальная-итерация). На каждой итерации проверяются JSON и границы diff, затем показывается существующий showcase/Gameplay. Это узкое исключение из требования запускать tests после каждого изменения content values. Изменения gameplay, schema, IDs, ссылок, collider, import pivot/PPU и runtime lifecycle в исключение не входят.

Обязательный набор acceptance IP сохраняется. Preview не является Verified. Единый runner выбирает REST для открытого Editor и batch для закрытого; запреты режима UnitySkills не обходятся. Повторное использование проверки допустимо только как явно обозначенное историческое evidence с той же проверенной версией inputs и исходной датой.

## Последствия

Синхронизированы WORKFLOW, Asset Pipeline, content-json rules и smoke-check. Game/Content/UI design, модель Codex и Execution order не меняются. Существующие regression tests сохраняются; экономия достигается пакетной подготовкой, меньшим количеством промежуточных прогонов и компактным результатом команды.
