# DECISION-0033 — Правила подбора Зелья лечения и Книги

Status: Approved
Date: 2026-09-21
Related IP: IP-09, IP-18, IP-19, IP-20, IP-26, IP-28, IP-29, IP-30
Related content IDs: PICKUP-001; production Book ID остаётся у IP-30

## Context

G-10 удерживал world pickup framework: не были согласованы full-HP consumption,
связь с XP radius, lifetime/reachability, приоритет drop overrides и обработка
одновременного подбора. Production числа не нужны для synthetic framework.

## Decision

1. При полном HP зелье всё равно подбирается и исчезает. Actual healing равно 0;
   эффекты «при подборе зелья» срабатывают с учётом собственных условий/cooldown.
2. Зелье и Книга подбираются при контакте с игроком. Бонус XP pickup radius на
   них не действует; параметры contact geometry задаются отдельно.
3. По умолчанию предмет лежит до подбора или конца забега. Если content задаёт
   время жизни, таймер останавливается на паузе. Lifetime измеряется в секундах
   running-time; отсутствие таймера означает отсутствие timed expiry.
4. Выпадение за границей поля или внутри препятствия переносится в ближайшую
   доступную игроку точку. Это правило для Зелья/Книги, не изменение XP lifecycle.
5. Для potion drop chance используется первое заданное значение: override типа
   врага → override поля → общий base chance. Явный 0 — заданное значение, не
   отсутствие override. Затем применяется относительный multiplier персонажа;
   итог ограничен 100%.

   `p = min(1, b × m)`, где `p` — итоговая вероятность [0, 1], `b` — выбранная
   базовая вероятность [0, 1], `m` — неотрицательный безразмерный multiplier.
   Например, `b = 0.05`, bonus +60% (`m = 1.6`) дают `p = 0.08` (8%);
   `b = 0.8`, `m = 1.6` дают `p = 1` (100%). Значения обязаны быть конечными.
6. Подборы обрабатываются в стабильном порядке. Если Книга ставит игру на паузу,
   оставшиеся предметы откладываются до продолжения running gameplay. После
   смерти игрока или завершения забега новых наград нет. Уже применённые награды
   не отменяются; duplicate collect не даёт повторной награды (контракт IP-28).

Обычные правила Книги из DECISION-0019/0020/0022 сохраняются: без XP/level,
общая очередь/controls, немедленная валюта только при пустом pool в момент подбора.

## Consequences

G-10 semantics закрыты. IP-28 реализует правила на FIXTURE-* данных, с тестами
полного HP, contact/XP independence, pause/lifetime, reachable drop, override/cap,
duplicate/simultaneous/terminal cases. Технический ключ стабильной сортировки и
алгоритм поиска доступной точки документируются реализацией; новые продуктовые
исключения из этих правил не подразумеваются.

Production base chance/heal, изображения и drop bindings остаются IP-20;
production Book card/ID/параметры/art — IP-30. Это approval правил, не доказательство
их реализации, не утверждение production balance и не закрытие IP-12A density review.

## Approval

Пользователь 2026-09-21 ответил «подтверждаю» на предложение всех шести правил
в этой задаче. Канонические GDD/CD, IP-28, consumer gates и STATUS синхронизированы.
