# DECISION-0054 — Автономное исполнение FIELD-001 и конкретизации F1-01

Status: Approved (делегированное решение исполнителя по прямому поручению пользователя)
Date: 2026-09-24
Related IP: IP-17 (F1-01), весь этап [FIELD-001](../implementation/milestones/FIELD-001-start.md)
Related content IDs: SKILL-001…007, SKILL-010, SKILL-013, SKILL-014

## Context

2026-09-24 пользователь поручил пройти F1-00…F1-09 без остановки на каждом шаге:
«принимай решения по текущему состоянию сама… заводи новые DECISION-записи там,
где раньше требовалось моё решение, фиксируя выбор и обоснование»; арт «готовь и
подключай по scripts/README.md / docs/art/ASSET_PIPELINE.md… я не буду проверять
картинки заранее — если что-то не понравится, поправлю сама вручную»; остановка —
только на решении без опоры в репозитории.

Работа идёт в облачном Linux-контейнере без Unity Editor: загрузка Unity и
лицензирование недоступны, `scripts/check_project.py` даёт NOT RUN. Инструмента
генерации изображений в этой среде нет.

## Decision

### 1. Протокол автономии

- Решения, которые раньше ждали пользователя, записываются здесь или в новых
  DECISION со статусом «Approved (делегированное…)» и обоснованием из GDD/CD/baseline.
- Approval арт-пакетов оформляется ссылкой на цитату выше; manifest stage остаётся
  `Prepared` до Unity import и игровой проверки — делегирование не выдаётся за
  визуальную приёмку.

### 2. Проверки без Unity

Вместо safe smoke каждый пакет проходит .NET 8 harness: все asmdef компилируются
против UnityEngine reference assemblies (патчи для API Unity 6, заглушки
Editor/TestTools/InputSystem, реальное IL математических типов), затем NUnit-тесты,
не требующие native runtime, исполняются и сравниваются с baseline HEAD. Тесты с
GameObject/физикой/сценами — NOT RUN. Поэтому пакет с кодом получает максимум
`Implemented`; `Verified` требует Unity-прогона на машине пользователя
(`python scripts/check_project.py --scope full`). Harness — инструмент сессии, не
часть репозитория и не evidence Unity.

### 3. Арт без генератора

Порядок предпочтения: (а) переиспользовать approved изображения; (б) производить
новое изображение из уже утверждённого мастера (crop/mask/rotate) — стиль и
палитра остаются утверждёнными; (в) процедурный VFX там, где Art Production
указывает «Procedural in Unity / Hybrid». Изображения, которые нельзя получить
этими способами, остаются названным art gate пакета с явным отсутствием, без
подмены fixture-картинками.

### 3a. Git LFS недоступен для записи

Сетевая политика среды блокирует `lfs.github.com` (verify-шаг загрузки даёт 403,
объекты не финализируются на сервере). Новые PNG этой сессии коммитятся обычными
git blob через явный список путей в конце `.gitattributes`; существующие LFS-файлы
не затрагиваются. Перевод в LFS позже: удалить эти строки, выполнить
`git rm --cached <пути> && git add <пути>` и закоммитить.

### 4. Технические конкретизации F1-01

Опираются на карточки и baseline v1 (DECISION-0053); новых продуктовых чисел нет.

- **SKILL-003 непрерывная орбита.** Новый флаг `persistent` у Orbit: состояние
  живёт у executor, умение обновляет его каждые 0.2 s (технический refresh в JSON,
  не показывается как cooldown в draft). Нет обновления ≥ max(1 s, 4×refresh)
  running time — орбита снимается. Попадания — по заметённому пути клинка
  (capsule overlap, шаг ≤15°), per-blade/per-target 0.6 s. Смена уровня сохраняет
  фазу; action speed не создаёт копий. Knockback радиально от персонажа.
- **SKILL-004 волна.** `Area.expansionSeconds` 0.25: фронт растёт от 0 до radius
  вокруг позиции персонажа в момент старта волны (центр не следует за игроком),
  каждая цель — один раз за волну, knockback радиально от центра. Вторая волна —
  отдельная wave c задержкой 0.35 s и собственным центром.
- **SKILL-010 удары.** Новый эффект `Strike` (radius, telegraph). Первый удар
  фиксирует позицию цели активации; следующие (шаг 0.3 s) в момент начала своего
  telegraph выбирают новую случайную живую цель в targeting radius вокруг текущей
  позиции персонажа, исключая уже выбранные жизни; нет цели — удар пропускается.
  Смерть/уход цели после snapshot не переносит удар. Knockback от центра удара.
- **SKILL-014.** Targeting `Self` + layout `IndependentRandom` — поведение
  baseline «FixedAxes»: направление не зависит от врагов.
- **SKILL-001 L3/L6.** Существующее `distinctNearestTargets`: при меньшем числе
  валидных целей в радиусе бросается столько камней, сколько целей.
- **Презентация.** Иглы, копьё и осколок — производные approved иконок
  SKILL-002/005/013 (сторона наконечника +X); волна, цепь и telegraph/impact —
  процедурные формы (`SkillWorldEffects.json`, палитра Art Direction §9.2/§12).

### 5. Конкретизации F1-03

- **CHAR-001 визуал.** Утверждённое тело гоблина (связь CHAR-001 ↔ fixture goblin
  подтверждена пользователем ранее) регистрируется production ID
  `CHAR-001-VISUAL-BODY` c тем же файлом и contact profile; portrait/icon выбора —
  тот же спрайт (`CHAR-001-VISUAL-PORTRAIT`/`-ICON`, scale-to-fit), motion
  `CHAR-001-MOTION` — копия утверждённого goblin-профиля. Новых изображений нет.
- **Draft weights.** В production definition только десять стартовых skills
  (1.35 для 002/005/007, 0.70 для 014, 1 для остальных); веса поздних ID остаются
  в baseline JSON до их production-определений: registry не содержит поздних skills,
  а locked ID всё равно фильтруются до розыгрыша.
- **Highlights.** У Клёпки нет отклонений от базовых характеристик, поэтому
  stat-highlights пусты (разрешённое «нет highlights»); тексты baseline выводятся
  в строке роли персонажа.
- **Миграция профиля.** Формат профиля не меняется (schema 1). При загрузке
  сохранённые прохождения досчитывают бесплатные unlocks нового mapping без валюты
  и receipts; прежние unlocks/покупки не отзываются; изменение сразу сохраняется.
  Путь production-файла профиля и переключение gameplay composition на production
  роли выполняются в F1-08 (сейчас сцена использует fixture-профиль).

### 6. Конкретизации F1-04

- **Каденция стрелков.** Новый `EnemyAttackCadence.WindupStartToStart` у атак
  ENEMY-004/005: первый замах через полный cooldown после spawn, интервал считается
  от начала замаха до начала следующего, прицел фиксируется в начале замаха; враг
  продолжает движение. Fixture и боссы сохраняют прежнюю каденцию по умолчанию.
- **Лучник.** Новый kind `DistanceReposition`: цикл 3 s = 2 s удержание дистанции
  6±0.5 + 1 s касательное движение (strength 0.5) с коррекцией дистанции, сторона
  меняется каждый цикл, скорость нормирована.
- **Гончая.** Существующий `TelegraphedDash` уже совпадает с baseline (первый рывок
  через 4.5 s, направление фиксируется в начале telegraph, стоит во время telegraph,
  dash contact KB 0.65 через общий contact timer); код не менялся.
- **Визуал.** Тела ENEMY-001/002 — уже принятые изображения (production sprite ID
  с прежним contact profile). Тела ENEMY-003/004/005/007 требуют генерации
  изображения, которой в этой среде нет: definitions не ссылаются на visual,
  runtime показывает явный placeholder, gate остаётся открытым (не fixture-картинка).
  Снаряды: камень пращи — производная approved камня SKILL-001 с коралловым
  «враждебным» ободком; стрела — процедурный рисунок в контурном стиле (Art Direction §12).
- **Пикапы.** Геймплейные значения PICKUP-001/002 — из baseline; масштабы спрайтов
  (0.68/0.7, XP 0.62) — уже принятые в игре 2026-09-22, а не нейтральные 1.0 review-формата.

### 7. Конкретизации F1-05

- **«Уже замедленная цель».** `CombatDamageRequest` несёт условные бонусы
  (фактор урона, аддитивный бонус outgoing knockback); `EnemyRuntime` применяет их
  один раз, только если цель была замедлена до текущего удара, до применения его
  собственного slow и до resistance. Бонус урона складывается в канал damage
  multiplier активации (фактор = (M+bonus)/M), knockback — в outgoing multiplier.
- **Новые семейства set-эффектов.** `SlowedTargetBonus` (skill-specific либо для
  всех умений игрока и set-атак — SET-004) и `OrbitSlowAura` (SET-010: каждые 0.1 s
  slow 15%/0.25 s по врагам в текущем радиусе живой persistent-орбиты, собственный
  source, без урона и hit feedback; без орбиты не действует).
- **SET-017.** Шаблон атаки `SET-017-ATTACK` (Strike 150/2.2/0.65, RandomEnemy 8)
  в отдельном `ProductionSetAttacks.json`, в draft не попадает; `scalesWithSizeAndRange`
  включает generic size/range только для этой set-атаки; первая попытка через
  полные 7.5 s, без цели интервал всё равно расходуется, action speed не влияет,
  активацией умения не считается.
- **Fixture-контракт.** Новые семейства добавлены в существующий FIXTURE-SET-GUARD
  (тест требует fixture для каждого семейства); аура там неактивна, т.к. fixture-орбита
  не persistent, поэтому fixture-поведение практически не меняется.

### 8. Конкретизации F1-06

- **BOSS-001.** Атаки — собственные inline-носители (`BOSS-001-FAN/RING` и
  `…-ENRAGED` с интервалом 2.88 s), без импорта ordinary ID. Режим встречи
  `keepAttackOrderOnPhaseChange` + `strictHealthThreshold`: фаза 2 наступает строго
  ниже 50% HP, текущий замах и уже идущий интервал не меняются, чередование
  веер/кольцо продолжается, новые интервалы — 2.88 s. Каденция wind-up start-to-start,
  первый замах через 3.6 s после появления, веер целится в позицию игрока на старте
  замаха, кольцо — `fixedOrientation` (0°, шаг 36°). Fixture-боссы сохраняют прежнюю
  политику (сброс очереди, порог ≤).
- **MIDBOSS-001.** Общий `TelegraphedDash` получил `dashCount`/`followUpTelegraphSeconds`:
  пара рывков 0.65→0.45 и 0.35→0.45 s с новым направлением на старте второго telegraph,
  затем 5.5 s преследования (первая пара тоже через 5.5 s). Фазы без атак разрешены
  (дальних атак у мини-босса нет).
- **Визуал.** Тела BOSS-001/MIDBOSS-001 и снаряды веера/кольца требуют генерации —
  открытый art gate; runtime показывает явные placeholders.

### 9. Конкретизации F1-08

- **Выбор composition.** Content следует экономике профиля. Реальный запуск
  (`Start()`) использует production `MetaCatalog` и отдельный файл
  `profile-v1.json`: прежний `fixture-profile-v1.json` прототипа не читается и не
  мигрирует, так как его unlock/currency относятся к fixture-экономике
  (DECISION-0050 mapping другой). Production профиль собирает только стартовые
  production definitions (`FixtureRuntimeContentCatalog.CreateProduction()`) без
  fixture fallback. Fixture-профиль (тесты, прототипные инструменты) по-прежнему
  собирает fixture-каталог, поэтому существующие сценовые тесты не меняют поведение.
- **Геометрия FIELD-001.** Используется сцена `Gameplay` c уже запечённой границей
  200×200 и объектом `SpawnPoint` (в (0,0)). Baseline называет `wallThickness 1` и
  `spawnPointName PlayerSpawn`; сцена имеет стены толщиной 0.5 снаружи края 200 и
  имя `SpawnPoint`. Внутренний размер 200×200 и старт совпадают, поэтому сцена не
  переименовывается и не перестраивается: толщина стены вне игровой площади на
  геймплей не влияет, а правка сцены без Unity рискованна. Отличие — техническое,
  не продуктовое.
- **Препятствия.** 64 прямоугольника baseline (пень 1.2×1.0, плетень 2.4×0.5)
  переносятся в presentation JSON как authored `obstacles`; runtime создаёт на
  каждый `BoxCollider2D` точно этого размера, взаимодействующий только со слоем
  Player (как DECISION-0045), со спрайтом, масштабированным по ширине прямоугольника.
  Случайный генератор интерьерных препятствий в этом режиме не используется;
  прототипный `Obstacle_Fixture` сцены скрыт и его collider выключен на время забега
  (восстанавливается при Dispose). Pickup/Traveler placement получают те же bounds.
- **Timeline/run setup.** Seeds волн/draft — `randomness.referenceSeeds` baseline;
  все wave multipliers baseline v1 равны 1 (генератор отказывает иначе); фазы
  непрерывны и покрывают ровно 900 s.

## Consequences

Код: `OrbitEffect.Persistent`, `AreaEffect.ExpansionSeconds`, `StrikeEffect`,
состояния executor и `SkillWorldEffectPresenter`; production JSON генерируется
`scripts/generate_field001_content.py` из baseline v1. Fixture-поведение не
меняется (новые поля по умолчанию нейтральны). Gameplay composition остаётся на
fixture-каталоге до F1-03/F1-08. Canon GDD/CD не меняется: пункты 4 — реализация
уже описанного поведения.
