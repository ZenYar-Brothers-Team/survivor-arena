# DECISION-0145 — Алтарный просмотр непосредственно на FIELD-007

Дата: 2026-10-02. Approved по прямому поручению пользователя: работать сразу в настоящей карте, назначить её землю, сделать выбор после Dev-разблокировки, временно использовать волны первой карты, случайно разместить 36 алтарей с равномерностью по типам/эффектам и максимум тремя на экране.

Основание: [DECISION-0135](0135-altars-mechanic.md). Назначение механики FIELD-007 теперь принято для этого игрового просмотра. Это не приёмка окончательного баланса позднего поля.

## Точный поднабор

- Поле имеет стабильные `FIELD-007`, `FIELD-007-ENVIRONMENT`, `FIELD-007-PRESENTATION`, название «Монастырские сады», difficulty 4, миниатюру и `FIELD-007-VISUAL-GROUND`. Это обычная карточка среди десяти полей; новый dev-ID не создаётся.
- Существующая кнопка Dev «открыть всех героев и поля» открывает FIELD-007 через ProfileService. Стандартное условие FIELD-006/12000 убийств сохраняется; кнопка не делает карту исходно открытой на свежем профиле.
- Временно напрямую используются timeline, ordinary pool, боссы и Путники FIELD-001. После этого прохода монастырю ещё нужны собственные encounters из канонического дизайна; номера boss/mid-boss 007 не переопределены в каноне.
- Накопление и воздействие на всех отсутствуют. Удары — эффект циклического алтаря. Для негативных ударов урон врагам равен нулю. Общая поддержка прежних эффектов и исторического «Тест 07» остаётся в foundation.
- Равномерность для первого просмотра утверждена ответом пользователя: три группы по 12 — позитивные циклические, негативные циклические, позитивные святыни. Внутри каждой группы числа эффектов отличаются не более чем на один. Пять позитивных циклических эффектов имеют counts 3/3/2/2/2; два негативных 6/6; две святыни 6/6. Это состав данного поля, не обязательный закон всех карт.
- Первоначальный размер 160×160 изменён прямым отзывом пользователя 2026-10-02 на 120×120 для более плотного расположения. Число 36 и состав 12 + 12 + 12 сохраняются; плотность возрастает в (160/120)² ≈ 1.78 раза. Численные эффекты/тайминги остаются временными параметрами авторинга для просмотра. Малые препятствия и монастырский decor pack добавляются отдельным проходом; текущий просмотр оставляет открытый пол вокруг алтарей, чтобы проверить механику и читаемость.

Authoring: [field007-altars-v1.json](../balance/field007-altars-v1.json). Generated Fields и FieldEnvironmentPresentation производит общий content generator.

## Случайная расстановка и плотность

Каждый забег получает свежий seed; reference seed закрепляется только существующим dev-переключателем. Центры не двигаются во время забега. Расстановка соблюдает края, стартовую безопасную область и зазор между областями эффектов.

`maxPerScreen = 3` ограничивает число оснований, а не число пересекающих экран областей действия. Размер окна берётся из актуальной ортографической камеры при старте. Для запаса на видимую высоту/ширину props окно расширяется на `screenPadding = 2` world units с каждой стороны. Проверяются все скользящие положения прямоугольника, включая центры по обе стороны условной границы ячейки. Неудачная раскладка повторяется в пределах configured attempts/restarts и не заменяется молчаливым нарушением лимита.

При изменении aspect/zoom во время уже начатого забега расстановка сохраняется; лимит относится к камере, с которой создавался забег. Следующий забег пересчитывает его по новому viewport. Адаптивное перерасположение посреди забега этим проходом не вводится.

## Представление

### Уточнение длительности наград

По прямому поручению пользователя (2026-10-02), уточнённому «давай 20 секунд а не 15»,
награды FIELD-007-SHRINE-EXPERIENCE и FIELD-007-SHRINE-POWER длятся по 20 секунд.
Это заменяет их предыдущие 30 секунд; опыт остаётся ×5, скорость действий — ×2
(`rewardActionSpeedBonus=1`). Время зарядки и cooldown не меняются.

### Уточнение пользователя: мини-карта и разные радиусы

По игровому отзыву 2026-10-02 все 36 алтарей показываются на существующей Dev мини-карте, включая спящие и находящиеся за экраном. Позитивное основание и святыня обозначаются кругом, негативное — зубчатой формой; цвет берётся из полярности, значков эффектов нет. Лёгкий контур показывает реальный радиус; активность меняет яркость. Карта остаётся скрытой до прежней кнопки «Показать карту» и недоступной вне development builds.

Для каждого экземпляра при расстановке выбирается равномерный случайный радиус в world units, сохраняемый весь забег. Рабочее численное толкование «максимальный чуть больше текущего, диапазон ×3»: `r_max = 1.125 × r_old`, `r_min = r_max / 3`. Старые 4 становятся 1.5–4.5, 8 — 3–9, 5 — 1.875–5.625. Максимум на 12.5% выше прежнего; это параметр данного preview, не правило всех полей. Один actual radius используется в clearance, containment, boundary и мини-карте. Радиус отдельных ударных кругов остаётся 2.5, а их центры выбираются внутри actual radius минус радиус круга; минимальный алтарь должен быть строго больше круга. Наградный взрыв святыни сохраняет отдельный radius из баланса. Обновление 2026-10-02 по прямому указанию пользователя: минимум каждого радиуса ×1.5 (2.25 / 4.5 / 2.8125 для прежних 4.5 / 9 / 5.625-алтарей), максимум для всех алтарей и святынь — 5 (диаметр = высота экрана, референс 10 world units). Позиции расставляются так, чтобы каждая полярность равномерно покрывала арену: `zoneLayout.polarityMixCandidates` = 24 допустимых центра на алтарь, выбирается самый удалённый от ближайшего алтаря той же полярности.

API-проекция: `IMapPreviewSource.Altars` → `MapPreviewViewState.Altars`; Bootstrap передаёт read-only снимки без UI-владения runtime. Поддержка `minRadius`/`ZonePlacement.Radius` следует существующему общему zone contract; `StrikeCenter` принимает actual radius как optional аргумент. Старые fixed-radius definitions сохраняют прежнее поведение. Число объектов, counts и screen cap сохраняются.

### Уточнение пользователя: физическое основание

По последующему прямому требованию игрок не проходит сквозь алтарь. Bootstrap создаёт один non-trigger CircleCollider2D основания для каждого из 36 объектов, только для слоя Player, по тому же player-only контракту, что остальные препятствия поля. Эти значения не зависят от effect radius: cyclic contact radius 0.28 wu / offset Y 0.15; shrine 0.42 / 0.18. Это стартовый fit к небольшому основанию, не ко всему высокому sprite и не ко всей зоне действия. Параметры авторятся в `altarPresentation`, проверяются profile constructor и применяются `AltarObstacleFactory`; body renderer остаётся visual-only. Контакт не исчезает во время отдыха/вне near window и удаляется вместе с field root на Shutdown. Это заменяет прежнее утверждение ниже об отсутствии physical contact у всего объекта.

По запросу о более ясном inactive/active feedback подготовлен и затем прямо утверждён к реализации [вариант с референсами](../implementation/proposals/2026-10-02-altar-state-presentation.md). Большая окружность показывает только actual effect radius. Постоянное небольшое кольцо у основания заполняется в отдыхе и опустошается в активном цикле; у святыни показывает charge/cooldown. Локальный свет навершия включается только в authoritative active state, у готовой святыни слабее и усиливается по charge; переход сопровождается короткой вспышкой. Body сохраняет постоянный цвет основания. Run clock замораживает весь feedback на pause; gameplay/collider transform не анимируются. Численные visual параметры — в altarPresentation.

Первоначальный набор имел общее навершие-молнию и один образ святыни. Последующее поручение [DECISION-0150](0150-field007-altar-type-visuals.md) заменяет запрет отдельных образов по эффектам: каждый тип имеет своё навершие/реликвию. Прежние круглое бирюзовое позитивное и зубчатое фиолетово-коралловое негативное основания сохраняются. Большой контур получает общий нейтральный плетёный рисунок при прежнем полярностном цвете; внутренняя дуга читается ярче. Все 14 новых PNG прямо выбраны пользователем; actual radius проходит по середине двух нитей контура.

Body не имеет collider и не меняет gameplay root. Граница области и progress/rest arc — отдельные прозрачные слои. Body сохраняется в ожидании, активность повышает яркость. Святыня показывает заполнение перед наградой, после срабатывания — восстановление. Удар использует существующие предупреждение/вспышку. Вся анимация следует замороженному на pause/terminal zone clock; Shutdown удаляет owned props, rings и materials.

Пакет: [field007-altars-v1](../../Art/Packets/field007-altars-v1.json). Технический downscale/alpha-noise cleanup не заменяет visual acceptance в игровом масштабе.
