# Сохранённая основа FIELD-003 — v4

Пользователь принял характер дорог 2026-10-02 («Мне нравится. …сохрани схему»).
Основание: [DECISION-0137](../../../decisions/0137-field003-road-network-concept.md).
[Порядок переноса в игру](../../../implementation/milestones/FIELD-003-road-network.md).

Этот каталог фиксирует принятую версию отдельно от дальнейших экспериментов.
`profile.json` — параметры и ориентиры; `generate.py` и `study_v4.py` — сохранённая
референсная реализация; `layouts-v4.png/svg` — принятые схемы; `accepted-metrics.json`
— результаты их исходного измерения; `reference-layouts.json` — координаты осей
дорог, входов/округлых концов и книг для шести seed. `manifest.json` содержит
SHA-256 файлов снимка. Изменение снимка — новая явно принятая версия.

Координаты в [0,200]²; для Unity арены с центром (0,0) вычесть (100,100).
Все длины в мировых единицах; ширина осевой линии не является коллайдером.
Поверхность дороги получается расширением её оси на половину ширины; тупик
дополнительно включает круг радиуса 6 вокруг `endCenter`. Книга в `bookPosition`.
Все поверхности должны объединяться перед построением player-only границы.

Профиль — контракт для переноса, **не DTO текущего Unity-каталога**. Подключение
через authoring источники и `scripts/content/generate.py` выполняется в этапе
переноса, без ручного изменения generated JSON. Python/scipy не требуются в
игровом процессе: алгоритм переносится в C#, профиль — в соответствующий DTO.

`python docs/prototypes/field003-roads/approved-v4/study_v4.py` воспроизводит
геометрию, экспортирует координаты и сравнивает длины дорог/тупиков и число
книг с принятой серией. Время может отличаться; исходные картинки не перезаписываются.
Различия RNG между Python и C# допустимы для новых seed при сохранении правил;
сохранённые координаты дают точные эталоны для сравнения геометрии и коллайдеров.

Принята форма сети и стартовые настройки. Гарантии любых seed, Unity collisions,
время игровой генерации и оставшиеся продуктовые вопросы не считаются решёнными
самой визуальной приёмкой. Текущий execution status хранится только в STATUS.
