# FIELD-003: расстояние между развилками и цель 15 тупиков

Серия сохранена для сравнения; пользователь счёл её слишком плотной.
Последующая проба — [редкая сеть v4](README-v4.md), с гибкими числами тупиков
и максимума пути, приоритетом разнообразия и редкости участков <2H.

2026-10-01. Основание — [DECISION-0137](../../decisions/0137-field003-road-network-concept.md).
Исследование v3; production данные/сцена/арт не меняются.

## Параметр

`Lmax` — максимальная длина пути по основной дорожной сети между узлами,
в которых доступно не менее трёх дорожных направлений. Единицы: мировые
единицы либо высоты экрана H=10. Изгиб дороги не является новым выбором.
Книжные ответвления не обнуляют расстояние: это наградные тупики, а не
альтернативные пути отхода. Периметр включён; цепочки через узлы степени 2
суммируются, поэтому поворот вокруг угла тоже не обнуляет расстояние.

Название «минимальный сегмент» не соответствует метрике: оптимизируется
**минимально достижимая верхняя граница** Lmax при сохранении числа тупиков.
Пользователь уменьшил цель до 15. Фраза «5% экрана» буквально означает
0.05H=0.5 единицы, при ширине дороги 0.8H=8. Раздельные перекрёстки с таким
шагом не получаются — поверхности сливаются. Точная единица первоначального
ограничения не подтверждена; 6H ниже — предложение по результатам исследования.

## Проверенные плотности

Каждая строка — шесть заранее выбранных seed: 17,42,91,123,256,777.
Размер поля 200×200, дороги 8, тупики 7×(20–40), округлый конец диаметром 12,
зазор между отдельными поверхностями 3. Верхнего лимита книг нет.

| Плотность | Наибольший участок между развилками, H | Тупики | Среднее число тупиков | Время карты, с |
|---|---:|---:|---:|---:|
| 16 случайных областей | 6.76–7.46 | 16–19 | 16.83 | 1.05–1.14 |
| 25 случайных областей | 5.38–5.88 | 12–18 | 15.00 | 1.36–1.45 |
| 36 случайных областей | 4.12–5.04 | 5–10 | 7.00 | 1.86–2.00 |

Вариант с 36 областями не выполняет прежний минимум 10 тупиков на пяти seed;
он оставлен в сравнении как отрицательный результат, не production-кандидат.
При выбранных 25 областях все шесть раскладок выполняют минимум 10, цель 15
достигается в среднем, не гарантируется точное число 15 в каждом забеге.

Предложение: ориентир **Lmax ≤6H (60 единиц)** и около 15 тупиков.
Это лучший компромисс среди проверенных вариантов, не глобальное доказательство
минимума и не гарантия ограничения на любых seed. Генератор измеряет Lmax,
но пока не исправляет локально нарушения для произвольного seed.

## Генерация без поиска целой карты повторными попытками

1. Разместить по одной случайно смещённой точке в каждом крупном секторе.
   Результат — области Вороного; дороги проходят по их общим границам.
   Из-за смещения получается сеть неправильных многоугольников и Т-развилок,
   а не прямоугольная дорожная решётка. Периметральная дорога остаётся общей.
2. Добавить выход из каждого угла периметра к ближайшему видимому внутреннему
   узлу: иначе длинные пути вокруг углов портят Lmax. Пересечение чужих дорог
   соединением запрещено; существующая видимая вершина проверяется напрямую.
3. Построить граф и измерить пути между узлами степени ≥3, включая периметр.
   Кратчайший цикл также измеряется отдельно. В выбранной серии он 85.56–106.88
   единиц: прежний Proposed порог v2 в 160 здесь не выдерживается. Размер циклов
   остаётся для visual review, нельзя заявлять его прежнюю приёмку.
4. Разместить ответвления в свободных областях, проверяя фактическую ширину.
   1200 локальных кандидатов, без перезапуска основного графа и без остановки
   на пятнадцатой книге. Их число зависит от свободного места.

Для вместимости текущей серии входы разнесены на 18 (1.8H), длины чаще короткие:
L=20+20u², u равномерно в [0,1], L в мировых единицах [20,40]. Например,
u=0.5 → L=25. Эти параметры Proposed. Длинные тупики 3–4H станут редкими;
средняя принятая длина 20.85–22.91. Это существенный компромисс плотной сети.

## Время и ограничения

Время измерено `time.perf_counter` на текущей машине: построение графа,
геометрии, подбор ответвлений и расчёт метрик. Отрисовка/сохранение PNG,
запуск Python, Unity import и Unity runtime в замер не входят.
Для 25 областей один граф занял 0.042–0.044 с, вся геометрия около 1.4 с.
Полных перегенераций графа в этой серии **0**. Это скорость исследовательского
Python-кода, не прогноз финального Unity генератора.

Граф измеряется по исходным осевым линиям. Близкие вершины могут образовать
один широкий перекрёсток; окончательный runtime-граф должен объединять их
до проверки навигации. Геометрия поверхностей дискретная, шаг 0.5; радиус
игрока/рывок не моделируются, дороги пока не имеют художественного оформления.
Острые соединения возле углов и сглаживание кромок требуют отдельного review.
Прежний Proposed angle gate v2 также не заявляется пройденным для v3.

Если вводить строгий production Lmax, следует локально добавлять перемычки
на самых длинных маршрутах либо менять крупные области, одновременно
сохраняя зарезервированные места для минимум 10 тупиков. Такое исправление
ещё не реализовано; массовая rejection-перегенерация не предлагается.
