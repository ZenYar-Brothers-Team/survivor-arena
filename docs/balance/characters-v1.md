# Персонажи CHAR-002…010 — данные v1

Ревизия: `characters-v1`, 2026-09-28. **Approved 2026-09-28** пользователем ([DECISION-0089](../decisions/0089-characters-v1.md)).
Это production data, не runtime JSON и не проверенный в игре баланс. Текущее
исполнение — только [STATUS](../implementation/STATUS.md). Таблица — [characters-v1.json](characters-v1.json),
проверка: `python -X utf8 docs/balance/validate_characters_v1.py`.

Точка отсчёта — CHAR-001 «Клёпка» из [baseline v1](field001-baseline-v1.md); сам CHAR-001 этот пакет не меняет.

## Направление пользователя (2026-09-28)

1. Каждому персонажу заблокировать пару активных умений и пару пассивок, чтобы **разные персонажи собирали
   разные сеты**.
2. Отличия по главным характеристикам сделать заметными: сильные стороны порядка **+30…+50%**, и дать
   **ослабление для баланса**.

## Правило весов драфта

| Вес | Что получает | Источник |
|---|---|---|
| **×1.35** | три активных умения из «повышенные» карточки | тот же множитель, что у CHAR-001 в baseline v1 |
| **×1.35** | три пассивки по образу персонажа | пользователь: у пассивок тоже есть веса по задумке |
| **0** | два активных умения из «пониженные» карточки | карточка + направление 1 |
| **0** | две пассивки на персонажа | направление 1, подбор ниже |
| ×1 | всё остальное | — |

Вес 0 разрешён GDD («вес может быть… равным нулю»). Заблокированное не выпадает ни в level-up, ни из Книги, ни при
reroll, а сеты с таким компонентом становятся недостижимыми и исчезают из списка достижимых рецептов на паузе
(используется существующая проверка `DraftPool.CanOffer`). Стартовое умение не блокируется никогда.

**Для кода новое:** веса пассивок уже есть в authoring baseline v1, но runtime сейчас применяет вес персонажа только
к активным умениям. GDD «веса выпадения умений» уточняется: к умениям относятся и пассивки (DECISION-0089).

## Характеристики: было в карточке → предлагается

Проценты — к CHAR-001 (100 HP, скорость 3, урон ×1, кулдаун ×1, радиус подбора 0.5). Кулдаун меньше 100% —
атакует чаще. Специализация стартового умения (DECISION-0075) не меняется.

|---|---|---|---|

## Открытие персонажей

Условия открытия и цены не меняются (DECISION-0050, MetaEconomy). Честным прохождением сейчас открываются Бугор,
Шепотка и Шмыга (FIELD-001…003). У остальных шести условие ссылается на FIELD-004…009, которых ещё нет; до них эти
персонажи доступны только через DEV-открытие.

## Что потребуется при реализации

- Генератор `scripts/content/actors.py` выпускает CHAR-002…010 из этого пакета; веса пассивок — новое поле
  runtime JSON и проверка `ValidateDraftSkillReferences` для пассивок; `DraftPool` применяет вес к пассивкам.
- Для CHAR-002…010 нужны portrait/icon (crop из утверждённого body) и motion profile; body уже импортированы.
- Content Design: карточки CHAR-002…010 (характеристики и строка Draft weights) и строка GDD про пассивки — только
  после утверждения.
- Тесты: стартовый snapshot каждого персонажа, веса 0 не выпадают, сеты с заблокированным компонентом
  недостижимы, стартовое умение каждого выдаётся.

## Механики стартовых умений (DECISION-0148)

Каждый персонаж получил механический бонус стартового умения с первого уровня (поле `startingSkillBoost` в [characters-v1.json](characters-v1.json) и baseline v1): Клёпка +1 рикошет, Бугор +1 клинок (damage-бонус +60% → +40%), Шепотка +1 пробивание, Шмыга +2 мины, Искра +1 цель цепи, Гром +1 удар, Вертун +1 бумеранг, Светляк второй луч, Иголка +1 пробивание, Ночка диагональные волны. Остальные числа этого пакета не менялись.
