## 1. Результат и границы

Игрок выбирает язык в Settings. Все player-facing тексты меню, забега, драфта, паузы,
результатов, меты и уведомлений показываются на выбранном языке без перезапуска.
Первая поставка содержит `ru`, `en`, `zh-Hans` и development-псевдолокаль. Добавление
языка второй волны требует только таблиц, шрифта и проверок, без изменения кода экранов.

### Out of scope

- **Языки волн 2–3.** Отдельный scope после стабилизации текстов.
- **RTL и сложные письменности.**
- **Страница Steam.** Её локализация не входит в IP.
- **Озвучка и локализованные изображения.** Растровых текстов в игре нет; при появлении —
  отдельное решение.
- **DEV drawer и development-поверхности.**
- **Telemetry-отчёты и balance tooling.**
- **Перевод канонических документов.**
- **Изменение формулировок.** Новые игровые тексты и правки смысла существующих не входят;
  перенос сохраняет текст дословно.

## 2. Архитектура и ownership

| Слой | Ответственность |
|---|---|
| `Assets/Game/Localization/` (новый asmdef, pure C#) | `LocaleId`, загрузка таблиц, `ILocalization.Get(key, args)`, правила множественного числа CLDR для поддерживаемых языков, форматирование чисел/процентов по культуре языка, fallback. Нет зависимостей на UI/Bootstrap |
| Runtime данные | `Assets/Resources/Localization/<locale>/ui.json` и `content.json` |
| Источник `ru/ui.json` | авторинг вручную (перенос литералов из C#/UXML и текстов эффектов сетов) |
| Источник `ru/content.json` | генерируется `scripts/content/generate.py` из Content Design и `MetaEconomy.json`; добавляется в `TARGETS` |
| Переводы | `scripts/localization/`: экспорт новых/устаревших ключей, AI-перевод с глоссарием, импорт, псевдолокаль, урезание шрифта. Результат коммитится; `generate.py` переводы не создаёт |
| Settings | поле `language` в `SettingsData`; `SettingsService` — единственный владелец текущего языка, событие смены |
| UI | презентеры и projections запрашивают строки по ключу; UXML содержит ключи, корень панели получает USS-класс языка для шрифта |
| Проверки | `scripts/localization/validate.py`, вызов из `scripts/check_project.py` |

Content definitions сохраняют стабильный ID. Имя сущности на экране берётся по ключу
`content.<ID>.name`, а не из поля `displayName`. Поле остаётся в JSON как русский источник
для генератора и диагностики (точная схема — L-02).

### Формат строки

- **Параметры.** Именованные: `"Урон +{percent}"`.
- **Ссылка на сущность.** `{ref:SKILL-003}` подставляет `content.SKILL-003.name` текущего
  языка.
- **Множественное число.** Поднабор ICU: `{count, plural, one {# монета} few {# монеты}
  many {# монет} other {# монеты}}`. Набор категорий обязателен по CLDR для каждого языка
  (`ru`: one/few/many/other; `en`: one/other; `zh-Hans`: other).
- **Метаданные ключа.** У каждого ключа исходной таблицы есть `context`
  (экран/элемент/смысл), необязательный `maxLength` и `sourceHash`, который хранится в
  переводах.

### Порядок fallback

1. Сначала выбранный язык.
2. Затем `en`.
3. Затем `ru`.
4. Если ключа нет нигде: в development показывается видимый маркер `⟦key⟧`, в release —
   `ru`-текст.

Release-сборка не должна содержать пропусков: проверка из §5 блокирует их до сборки.

## 4. Edge cases

- **Смена языка из Pause.** Pause, HUD и открытые карточки перерисовываются из
  ViewState. Уже показанные уведомления дорабатывают на прежнем языке. Состояние забега
  не меняется.
- **Сохранён удалённый или неизвестный код языка.** Применяется правило первого запуска;
  settings file не считается повреждённым.
- **Перевод повреждён или не загрузился.** Язык откатывается на `en` целиком, ошибка
  логируется. Повреждённые файлы переводов не смешиваются построчно.
- **Устаревший перевод** (`sourceHash` не совпадает). В development показывается
  переведённый текст с предупреждением в отчёте проверки, в release-проверке это ошибка.
- **Параметр отсутствует или лишний.** Validate — ошибка. Runtime в development —
  маркер, в release — текст без подстановки.
- **Числа.** Десятичный разделитель и формат процентов берутся по культуре выбранного
  языка. Внутренние форматы (сохранения, telemetry, JSON) остаются invariant.
- **Регистр.** Преобразование регистра — только с культурой выбранного языка; для
  турецкого не использовать invariant `ToUpper`.
- **Профиль, сохранения и telemetry** продолжают хранить ID. Смена языка не меняет
  сохранённые данные.

## 5. Acceptance

1. **Проверка литералов.** `validate.py` не находит кириллицу и player-facing литералы
   в `Assets/Game/**/*.cs` и `*.uxml` вне таблиц. Исключения: `Tests/`, DEV-поверхности
   по явному allow-list и комментарии. Отчёт перечисляет каждое найденное место.
2. **Полнота таблиц.** Для каждого поставляемого языка каждый ключ исходника есть и не
   пуст. Если не проверено ни одной записи, результат — INCONCLUSIVE, а не PASS.
3. **Параметры и множественное число.** Множества параметров и `{ref:…}` совпадают с
   исходником. Plural-блоки содержат все категории CLDR языка.
4. **Длина.** `maxLength` соблюдён. Длина псевдолокали не превышает лимит после
   расширения на 35%.
5. **Глифы.** Каждый символ таблицы языка присутствует в шрифтах этого языка.
6. **Устаревшие переводы.** Для release нет переводов с несовпадающим `sourceHash`.
7. **Content-таблица.** `generate.py --check` проходит; `ru/content.json` содержит
   name/description всех production ID из generated JSON и META из `MetaEconomy.json`.
8. **EditMode.** Тесты покрывают:
   - plural rules ru/en/zh на 0, 1, 2, 5, 11, 21, 22, 25, 111;
   - подстановку параметров и `{ref:…}`;
   - fallback;
   - неизвестный код языка;
   - повреждённую таблицу;
   - выбор языка при первом запуске;
   - сохранение и загрузку `language`.
9. **PlayMode.** Смена языка из Main Menu и из Pause перерисовывает видимые тексты без
   перезапуска; состояние паузы и забега сохраняется.
10. **Ручной просмотр.** Все экраны на `qps`, `en` и `zh-Hans` при 1280×720 и 1920×1080:
    нет переполнений и «квадратиков»; на `ru` тексты совпадают с текущими дословно.
11. **Вычитка.** Английский вычитан пользователем; китайский — носителем; результат
    записан в evidence.
