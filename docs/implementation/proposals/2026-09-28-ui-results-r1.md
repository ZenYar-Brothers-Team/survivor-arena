## Один экран, три смысловых блока

1. **Исход и факты.** Крупное «Победа» / «Поражение»; для выхода — «Забег прерван»,
   для обработанной ошибки — «Забег остановлен». Под ним время, достигнутый уровень
   и убийства: три хорошо читаемых значения без длинного абзаца.
2. **Получено.** Самое заметное число — заработанная валюта за этот забег, не общий
   кошелёк. Ниже короткая разбивка «За уровень» / «За книги». Значения только из
   сохранённого receipt этого RunId, не новый расчёт награды во View.
3. **Коллекция.** Сверху — новые открытия, только если они действительно появились.
   Ниже — собранные сеты, компактные иконки с названиями. Не показывать
   внутренние content IDs и не выводить полный справочник ещё закрытого контента.

   Уточнение пользователя 2026-09-28: новые открытия включают не только сеты,
   но и обычные умения (активные/пассивные), персонажей и карты. Общий формат
   элемента: изображение, название, короткая подпись типа («Сет», «Умение»,
   «Персонаж», «Карта»). Разные типы используют одну прокручиваемую коллекцию,
   без отдельных пустых панелей. В runtime передавать типизированный список
   новых открытий сохранённого результата, а не только список set IDs.
   Смешанный пример макета не задаёт новые условия или пакеты открытия.

Внизу постоянные действия: «В меню» и основная «Ещё забег». Последняя немедленно
повторяет те же character/field, без подтверждения и возврата к выбору.
Новых кнопок магазина/развития в Results не добавлять.

## Компоновка и стиль

- 1920×1080: центральная панель; верх — исход, основная область в две колонки:
  слева факты/награда, справа открытия над собранными сетами; footer вне scroll.
- 1280×720: та же иерархия с меньшими отступами. Прокручивается только длинная
  коллекция; исход, награда и действия остаются видимыми. Проверить 20 сетов и
  длинные названия, а не только пустой результат.
- Принятые сливовые матовые поверхности, тёплый текст, золотой акцент награды и
  терракотовая primary button. Победа и поражение различаются заголовком/акцентом,
  а не отдельными перегруженными иллюстрациями. Новый generated art не требуется.
- Если сетов нет — одна короткая строка «Сеты не получены». Если новых открытий
  нет — их группа отсутствует, без пустого большого блока.

## Сохранение и ошибки

Согласованный запрос +20 золота за полученное из Книги улучшение входит в
«За книги». Точный контракт (не XP-level, пустая Книга только 50, отмена/повтор
не начисляют бонус) — DECISION-0090. Исполнение и проверки — в STATUS;
демонстрационные числа браузерного макета не являются расчётом экономики.

До подтверждённой записи не показывать награду как успешно полученную. При Saving
короткий статус; повтор забега заблокирован согласно текущему profile contract.
При ошибке — «Не удалось сохранить результат» и отдельное «Повторить сохранение».
Не открывать обход блокировки через новый run/покупку. Повтор сохранения не выдаёт
награды или уведомления повторно. Load/backup/reset остаются своим отдельным flow.

## Техническая граница переноса

Results и Meta сохраняют общий owner MetaScreen/MetaPresenter. Для чистовой
раскладки используются RunResultsProjection и типизированный RunResultsViewState,
без парсинга MetaPresenter.Summary и без переноса экономики во View.
Meta Progression этим срезом не переоформлять. Attribution top-3 skills не добавлять
до проверки готового источника точных данных; пустые или приблизительные рейтинги
не показывать. Gameplay/HUD/Draft/Pause/Entry остаются без изменений.

Проверки Unity-переноса: исходы, pending/error/retry save, точный receipt,
пустые/длинные коллекции, обе геометрии и Retry с тем же выбором.
