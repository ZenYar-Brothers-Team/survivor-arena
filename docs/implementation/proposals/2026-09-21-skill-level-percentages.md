# Процентные улучшения уровней active skills

Вариант A утверждён пользователем 2026-09-21: [DECISION-0021](../../decisions/0021-additive-skill-level-bonuses.md). Ниже сохранён материал ревью. Текущий execution status — только в [STATUS](../STATUS.md).

## Неопределённость

[Content Design, Active Skills](../../Content_design.md#active-skills) требует накопления изменений L2–L6 поверх предыдущих уровней. [Game Design](../../Game_design.md#активные-умения-пассивные-предметы-и-слоты) требует сложения процентных бонусов разных источников. Не зафиксировано, считаются ли повторные процентные улучшения уровней одного skill прибавками к исходному параметру или множителями его предыдущего значения.

Это определяет cumulative resolver IP-08 и числа будущего production-каталога IP-17. Существующие fixture definitions хранят готовые значения каждого уровня; они не являются решением для approved skill cards.

## Варианты для ревью

Для SKILL-001: base damage = 20, L2 даёт +30% damage, L6 добавляет +25% damage.

| Вариант | Расчёт L6 без внешних modifiers | Итог |
|---|---|---:|
| A — складывать бонусы уровней к базовому параметру | `20 × (1 + 0.30 + 0.25)` | 31 |
| B — умножать результат предыдущих улучшений | `20 × 1.30 × 1.25` | 32.5 |

Рекомендация: **A**, чтобы обычные процентные прибавки уровней следовали аддитивной модели и не создавали неявного сложного процента. Это предложение требует ответа пользователя; fixtures или технические defaults не утверждают его автоматически.

Решение относится к повторным процентным прибавкам числового параметра внутри active-skill progression. Явные абсолютные значения, например число projectiles, заменяют прежнее значение. Явно относительные дочерние эффекты («60% damage первого взрыва») сохраняют указанную связь. Правила внешних modifiers, action-speed denominator и snapshot из DECISION-0017 не меняются этим предложением.

## После решения

- Зафиксировать выбранную формулу и численный пример в Content Design; при необходимости уточнить связь с общей формулой GDD.
- Реализовать и проверить cumulative resolver IP-08, включая повторное получение одного уровня, скачок L1→L6 и независимость от порядка чтения definitions.
- Продолжить остальные требования IP-08 и последующие разрешённые модули до границы перед IP-31.
