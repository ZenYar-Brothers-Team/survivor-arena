# Переработанный Implementation Plan — проект для ревью

Материал ревью: план принят пользователем 2026-09-20 и зарегистрирован. [Действующий план](../../README.md), очередь и статусы — только в [STATUS](../../STATUS.md). Этот файл не является текущим implementation packet.

Дата: 2026-09-20. Ревизия проекта: `design-sync-R2`.

**План переработан через обновление существующих IP до их дальнейшей реализации.** Подготовлены полные целевые спецификации всех 30 действующих модулей и пяти новых. Порядок работы изменён: телеметрия и ручной цикл баланса идут до расширенных encounters и production-каталогов; мета-прогрессия и сквозной UI — до массового наполнения контентом. Стабильные номера IP сохраняются, но больше не задают порядок исполнения.

Пять новых документов уже утверждены пользователем. Три новые версии полностью заменили прежние Game Design, Content Design и Art Direction при регистрации. По последней поправке пользователя старые версии отдельно не сохраняются. Код и content JSON не изменены. Единственный источник текущих статусов — [STATUS.md](../../STATUS.md); этот каталог сохраняет материалы review, а действующие спецификации находятся в основном modules.

## Вехи поставки

В [05](05-migration-and-execution.md) сохранён согласованный проект очереди. Единственная рабочая Execution order теперь находится в STATUS.

1. **M-01:** полностью заменить три документа без архивных копий прежних версий, зарегистрировать целевые спецификации, зависимости, gates и порядок; синхронизировать selector в AGENTS.md/WORKFLOW.
2. **Обновлённая основа и ранняя обратная связь:** необходимые дельты core/draft/UI harness → IP-31/IP-32. Один реальный fixture run и прослеживаемый анализ доступны до bosses, Travelers, полного UI, meta и массового арта.
3. **Игровые системы:** обновлённые сеты, characters/presentation, enemies/waves, boss/field frameworks, pickups и Travelers. Каждый feature поставляет свои состояния UI и наблюдаемые события.
4. **Мета и сквозной UI:** IP-25/IP-26 подняты перед production-каталогами. Framework flow проверяется на явно тестовых данных; production economy требует заполненных согласованных значений. Недоступные данные не заменяются выдуманными ценами.
5. **Production по ID:** IP-17…IP-23 и IP-30, их изображения и UI-привязки, затем IP-24 с полными encounter schedules. Можно менять порядок независимых Ready packets и поставлять согласованные поднаборы. Остаток каталога явно сохраняется.
6. **IP-27:** сквозная проверка систем и полного объявленного контента, 15-минутные ручные прогоны, читаемость при нагрузке, persistence/retry и воспроизводимый balance review.

Заполненный тестовый framework, первый production набор и готовый полный каталог — разные результаты. Проверка одного набора не завершает весь catalog IP.

## Уже принятое и оставшиеся решения

Approval пяти документов относится к описанным правилам и **121 существующей target-карточке**. Старые Draft-метки не отменяют это решение пользователя. Оно не заполняет отсутствующие значения и не принимает будущие картинки или предложения AI.

| Условие | Как учитывается |
|---|---|
| Утверждённый дизайн | Повторный approval roster, трёх слотов, priority sets, Travelers и прочих заданных правил не требуется |
| G-01…G-18, W-01 | Конкретные внутренние противоречия/пропуски из 01; блокируют только зависящий packet |
| CG-01 | При M-01 отражает уже полученное approval нового каталога |
| CG-02/CG-03/CG-04 | Сохраняются фактически незаполненные schedules, экономика и timing/tuning data; число draft slots больше не TBD |
| AG-01 | Принят конкретный вариант изображения/замены, известны provenance и технические требования; затем runtime preparation/import |
| BG-01 | Принята конкретная revision balance proposal с проверяемым diff; после применения — проверки и повторный прогон |

Book как механика утверждена, но отдельная production card/ID отсутствует. IP-28 проверяет framework на fixtures; IP-20 поставляет PICKUP-001 и drop bindings; IP-30 — production Book после заполнения недостающей карточки. Существующий CHAR-001 concept approval не запрашивается повторно: сначала устанавливается соответствующий source/master, затем проверяется runtime integration.

Для review плана остаются разбиение и очередь, предложения по незаполненным правилам, порядок первых production ID и конкретные недостающие данные. Не нужно ждать заполнения всего каталога для работы над независимым подготовленным packet. Отдельный balance patch применяется только после его собственного approval, как запросил пользователь.

## Учёт .claude и репозиторных контрактов

Учтены семь path-scoped rules и helpers design-review, consistency-check, content-audit, balance-check, asset-audit, propagate-design-change, conventions-review, perf-audit, test-quality-review, smoke-check, regression-map, tech-debt, architecture-decision. Они не заменяют design sources или STATUS.

В спецификациях сохранены единое JSON-дерево и required fields без tuning defaults, NumericValidation, Shutdown/rollback, pooling, PerfGuard, один тип в файле, immutable ViewState/presenter, компактный DEV drawer, VisualRoot/single writer и semantic UI IDs. Синтаксический JSON hook из Claude не доказывает domain/reference validity и не предполагается автоматически работающим в другом клиенте.

Полный проект был подготовлен одним пакетом по прямому запросу пользователя, затем принят и зарегистрирован. В M-01 применены перечисленные изменения authority/selector и semantic ID rules. Read-only helpers не изменены. Изменения regression/debt registers в будущем выполняются по правилам соответствующих helpers.
