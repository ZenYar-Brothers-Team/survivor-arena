# UI layout R2 — предложение композиции «Полевой фолиант»

Date: 2026-09-28
Назначение: review композиции и плана доведения интерфейсов, с учётом
утверждённых пользовательских комментариев. Это не реестр execution status.
Утверждённые ограничения — [DECISION-0083](../../decisions/0083-player-ui-layout-and-dev-boundary.md)
и [DECISION-0086](../../decisions/0086-ui-review-density-and-inspection.md);
visual language — [DECISION-0081](../../decisions/0081-field-folio-ui-visual-language.md).

Композиция принята пользователем 2026-09-28 с последним увеличением портрета;
разрешён перенос в Unity (DECISION-0086). [Интерактивные макеты и запуск](ui-layout-r2/README.md).
Настоящие ассеты в постановочной HTML-сцене; это не capture Unity и не приёмка
живого боя. Переключаются HUD/Draft/Book/Pause/Controls и 1080p/720p.

Дополнение пользователя о параллельной работе: клавиатура остаётся default,
галочка Settings включает mouse movement; пауза — Escape / Space / ПКМ.
Единый контракт этой реализации — [DECISION-0084](../../decisions/0084-mouse-movement-and-pause-shortcuts.md).
Макет не меняет её файлы. При интеграции проверить отсутствие mouse-input capture
у неинтерактивного HUD/HP и двойного pause/submit по Space; draft/system pause и
открытые Settings не должны сниматься global shortcut. Bindings показываются
в Settings из актуального input source; в HUD текстовых подсказок нет.

## Что показал review первого стилевого прохода

| Наблюдение | Почему это мешает чистовой версии |
|---|---|
| USS-проход сохранил нижнюю общую полосу и большую правую панель билда | Временная геометрия стала восприниматься как целевой layout; свободный бой не был основой композиции |
| Скорость находится вне DEV и не gated через `SetDevelopmentControlsVisible` | Противоречит уточнённому назначению controls; требуется перенос и защита UI intent |
| Player HP закреплён снизу | Противоречит требованию следить за здоровьем рядом с героем |
| `option.Detail` содержит полный список preview values, повторяется в постоянном `draft-details` | Короткий эффект и справочная информация не разделены; карточка и нижняя панель дублируют текст |
| Pause использует высокие карточки в одном длинном scroll | Для взгляда на 6+6 слотов приходится прокручивать экран; разделы рецептов оказываются далеко внизу |
| Settings/Quit находятся в отдельном AppShell, отсутствующем в capture harness | Снимок одной Resume не проверяет всю настоящую паузу |
| PNG получены на однотонном фоне с fixture-текстом и без иконок/type labels | Пройдена проверка устойчивости layout, но не читаемости реального содержания |
| IP-10A фиксирует детали строго снизу и старый elapsed timer | Технические решения прототипа противоречат UI/UX, где подробности могут быть контекстными, а timer уже обратный |

Точки кода: `GameplayUi.uxml`, `GameplayUiStyles.uss`,
`GameplayUiPresenter.BuildDraftState`, `UiToolkitGameplayView.RenderDraft` /
`SetDevelopmentControlsVisible` / `RenderPauseBuild`, `AppShell.uxml` /
`AppShellStyles.uss`, `UiFoundationSmokeTests`.

## HUD

Композиция после комментариев:

```text
                    оставшееся время
                  boss HP, когда нужен

                         [ HP ]
                       персонаж
                  свободная игровая область

  active:  6 компактных слотов                 полученные sets
  passive: 6 компактных слотов
  уровень · тонкая XP-полоса
```

- HP: тонкая полоса чуть выше силуэта, с небольшим отступом; anchor следует за
  персонажем, не за фиксированным местом viewport. Точная позиция над/под силуэтом
  проверяется на реальном персонаже и эффектах. Числа current/max доступны в Pause.
- Timer остаётся главным индикатором конца run. Boss bar появляется отдельно от
  здоровья игрока; короткие notifications не перекрывают персонажа или выбор.
- Active/passive — две компактные строки по шесть слотов у нижнего левого края;
  acquired sets — небольшой блок справа. XP и уровень образуют низкий отдельный
  блок. Большая общая нижняя подложка и высокая правая «карточка билда» не нужны.
- Скорость, fixture labels и diagnostic stats — только DEV. Wave information
  и инструкции WASD/стрелок/Settings/Pause из player HUD убраны. Самой кнопки
  Pause тоже нет: пауза через Escape / Space / ПКМ.
- В 720p слоты active/passive/acquired уменьшены с 50 до 30 px, иконки с 44 до
  26,4 px, XP-блок с 347 до 208,2 px. Timer — 112×44 px. В 1080p сохранены
  прежние 50/44/347 px и размер timer; цифры уровней остаются читаемыми.
  Это размеры HTML-кандидата, не gameplay scale или новый minimum resolution.
- При движении у границ карты, camera follow/shake, pause, death и retry HP-anchor
  остаётся связан с правильным персонажем; UI не перехватывает movement input.

## Draft и Book

Центр внимания — три равноправные карточки, над ними короткий заголовок и только
нужная информация об очереди. Reroll и Banish с остатками — единая компактная
строка под выбором; cancel/hints используют те же места и не меняют смысл действий.

```text
                        выбор улучшения
                      origin / очередь

       [ карточка 1 ] [ карточка 2 ] [ карточка 3 ]
       тип / иконка    тип / иконка    тип / иконка
       имя / уровень  имя / уровень  имя / уровень
       эффект выбора  эффект выбора  эффект выбора
       число сетов    число сетов    число сетов
       [Выбрать]      [Выбрать]      [Выбрать]

       список связанных сетов  |  выбранный рецепт
       имя + прогресс, scroll  |  статус + краткий эффект + компоненты

                      Reroll · Banish
```

Бюджет информации — ориентир для макета, не правило обрезания данных:

| Слой | Содержание |
|---|---|
| Первый взгляд | Иконка, тип, имя, New или current→next level |
| Решение о выборе | Обычно 2–4 короткие строки эффекта/изменений; у нового умения — что оно делает |
| Синергия | В карточке только количество связанных сетов; у set-card готовность рецепта |
| Закреплённый просмотр | Список связанных сетов и прогресс слева; краткий эффект и компоненты выбранного справа |

Длинное описание заменено компактным inspector. Клик/keyboard activation тела
карточки только закрепляет просмотр. Hover/focus сами его не меняют. Изначально
закреплён первый вариант. Отдельная «Выбрать» на нём подтверждает; кнопки остальных
disabled и сохраняют позиции. Banish использует ту же схему с «Исключить».
Раскрытие рецептов не сдвигает карточки и не подкладывает confirm под указатель.

Слева видны несколько имён с прогрессом; при 6–10 рецептах список прокручивается,
не превращается в последовательное перелистывание стрелками. Выбор рецепта
сохраняет scroll и не отправляет selection. Справа — короткий статус «В процессе»,
«Завершит рецепт» или «Рецепт готов», краткий эффект сета и component levels.
Эффект — тот же минимальный текст, что во всплывашке Pause. Без поясняющих абзацев
о последующей выдаче сета; «Получен» по-прежнему только для acquired. При нуле
рецептов inspector скрыт, геометрия карточек/actions неизменна.

Список и счётчик включают только ещё не полученные достижимые meta-доступные
сеты. Недостижимые исключаются, готовые без получения остаются. Критерии
достижимости — DECISION-0073; в runtime данные предоставляет существующий owner,
не View. «Упущены» остаются в Pause, а не в Draft/Book.

Существенный новый эффект не прятать ради лимита строк. Краткий текст авторский,
не механическое обрезание: например «+1 рикошет. Повторный удар слабее» вместо
точного коэффициента damage/knockback. Runtime data/Detail не удаляются только
ради смены presentation; gameplay числа и рецепты остаются у прежних owners.

Уточнение [DECISION-0085](../../decisions/0085-ui-damage-percent-presentation.md):
доступ к числам не включает показ абсолютного базового урона. Его
не выводим, в том числе в details; прибавку урона показываем процентом. HP,
секунды, количества и recipe thresholds остаются в своих единицах.

Book использует ту же композицию и меняет origin/accent. На ревью показать
обычный level-up отдельно от Book; set card — с существующей иконкой, кратким
эффектом и free-slot marker; компоненты в inspector без дубля на карточке.
Состояния 0/1/2 вариантов сохраняют
семантику канонических §§7/12, не изобретают новый fallback.

## Pause / Build

Две области; приоритет площади — рецептам:

```text
  ПЕРСОНАЖ + БИЛД               СЕТЫ — общий scroll
  изображение / имя / HP        | Получены: иконки + названия
  stats                        рецепты — 3 / 2 колонки
  6 active + 6 passive          progress + components
                               | Упущены: иконки + названия

                    Resume · Settings · Quit Run
```

- Слева около трети ширины: имя/HP/stats, 6+6 компактных entries (иконка, имя,
  уровень). Все 12 слотов без scroll; подробный эффект контекстно.
  Область изображения персонажа увеличена: 100×96 px при 720p и 140×120 px при
  1080p. Это геометрия HTML-кандидата, не новый размер production sprite.
- Скорость — `round(100 × current / baseline)`, current в world units/s ≥0,
  общий baseline CHARACTER-BASELINE-001 в world units/s >0, обе величины конечны.
  При baseline=3: current=3 → 100%, current=3,6 → 120%, включая старт быстрого
  героя. Не нормализовать относительно старта выбранного персонажа.
- Справа «Получены», затем рецепты в трёх колонках при 1920×1080 / двух при
  1280×720, затем «Упущены». Все три раздела в общем scroll; thresholds рецептов
  остаются видимыми, промежуток имя→уровень меньше. Acquired и missed — только
  icon/name с вертикальной чертой (золотой / приглушённой), без компонентов
  и постоянных описаний. Иконки 34 / 30 px, текст 18 / 16 px (1080p/720p).
  Больший список прокручивается, а не уменьшает текст; пустая группа скрыта.
- Нажатие любого сета справа открывает небольшую справку с основным эффектом.
  Крестик, клик снаружи, Escape или ПКМ закрывают её, не снимая паузу и не
  выполняя другое действие. Фокус возвращается на сет. Справка не двигает
  layout, не закрывает footer; scroll/resize/смена экрана закрывают её.
- Resume/Settings/Quit находятся в общем видимом footer вне scroll. Все три
  действия входят в композицию, даже если их presenters принадлежат разным owners.
- Слоты образуют две сетки по 2 колонки × 3 ряда. Вместимость
  достигается короткими rows и разумными промежутками.
  Empty/max/длинные имена не должны превращать весь экран в один scroll.

## Пересмотр плана доведения

Это последовательность работ внутри IP-10A/IP-26 и проверки IP-27. Текущая
очередь и готовность определяются только [STATUS](../STATUS.md).

1. **Контент и иерархия.** Отделить player/DEV и summary/details; сохранить
   утверждённые действия. Собрать реальные тексты и иконки для нового умения,
   upgrade, passive, set, progress/completing/missed и заполненного билда.
2. **Композиция.** Сделать reviewable макеты HUD/Draft/Pause в двух разрешениях
   поверх production поля, включая HP рядом с героем и все Pause actions.
   Учесть DECISION-0086; browser stress 10 связанных/20 общих рецептов помечать
   отдельно от настоящего контента. HTML-фон не заменяет live production review.
3. **Реализация.** Перекомпоновать UXML/View и разделить краткую/справочную подачу
   в ViewState/presenter; перенести speed в DEV с intent gating. UI по-прежнему
   не владеет gameplay state. Стили foundation не должны случайно менять ещё
   не переработанные selection/Meta/Settings; общий компонент допускает варианты.
4. **Целевые проверки.** Проверить production композицию, input/focus, release
   visibility, HP anchoring и полноту текста. Fixture long-text tests оставить
   отдельной стресс-проверкой; удалить лишь assertions, замораживающие старую
   геометрию, заменив проверками видимости, доступности и отсутствия перекрытий.
5. **Остальные экраны.** После приёмки первого среза: Main Menu и selection;
   затем Results/Meta; затем Settings. Для каждого сначала композиция и контент,
   потом применение общей темы. Количество действий и переходы сохраняются.

## Матрица приёмки нового среза

| Поверхность | Обязательный review |
|---|---|
| HUD | Production поле, начальный/полный билд, player HP рядом с героем, boss, читаемость во время боя |
| Draft | Три настоящие иконки и type markers; new/upgrade/passive/set, число/единица/изменение, recipe states; inspect не подтверждает, отдельный confirm выдаёт один intent |
| Book | Origin, очередь, общие reroll/banish, неполный пул и disabled controls |
| Pause | Production изображение/имя/stats/6+6/sets, baseline speed; доступные Resume/Settings/Quit; 3/2 колонки progress, компактные acquired/missed; краткая справка по нажатию любого сета |
| Input/states | Mouse hover, keyboard focus, pressed, selected, disabled, lock reason там, где locked content допустим, error/retry там, где применимо |
| Resolution | 1920×1080 и 1280×720, реальные длинные имена и кириллица, читаемость без маскировки overflow уменьшением шрифта |
| DEV/release | Release не содержит speed/DEV actions и не принимает их UI intents; Editor drawer по умолчанию закрыт |

У каждого review-кадра должны быть указаны разрешение, production/fixture,
состояние и наличие DEV. Синтетические подписи, пустые icon wells, тестовый 00:00
и кадр только GameplayUi без AppShell не принимаются за чистовую демонстрацию.
OFL-импорт шрифта подтверждает источник, но окончательное начертание заголовков
(в текущем проходе Medium вместо целевого SemiBold) требует проверки на этих кадрах.
