# UI entry R1 — интерактивный макет

[Предложение](../2026-09-28-ui-entry-r1.md). Это HTML review, не Unity и не новый
контент в игре. Execution status — [STATUS](../../STATUS.md).

Из корня репозитория:

```powershell
node docs/implementation/proposals/ui-entry-r1/serve-preview.cjs
```

Открыть [локальный макет](http://127.0.0.1:4180/). Сервер раздаёт только файлы
этого preview, существующие runtime Art и UI Fonts и пять явно перечисленных
preview PNG для D/E; GET/HEAD, loopback-only.
Порт можно задать `UI_ENTRY_PREVIEW_PORT`. Прямой `file://` не поддерживается:
ресурсные ссылки разрешаются от корня сервера. Интернет и Unity не нужны.

Верхняя панель — инструменты review, не игровой UI: выбор экрана, 720p/1080p,
три примера профиля и synthetic stress (10 героев / 15 полей). В обычном примере —
Клёпка, Бугор и десять полей. Бугор и FIELD-004…010 — approved content/art preview,
не production-подключение. У неполученных героев body показан силуэтом; поля
расположены в сетке 5×2 без описаний окружения и без scroll для десяти карточек.
Кнопки Meta/Settings/Exit/Start не выполняют реальных действий. Существующие
изображения и шрифты читаются из проекта без изменения импорта.

У главного меню пять вариантов с одинаковыми действиями и геометрией:
A — исходный пейзаж с отдельным гоблином; B — только пейзаж; C — герой на спокойной
плашке; [D — цельная сцена побега](http://127.0.0.1:4180/?menu=D). В D показана
версия 3: сосредоточенные гоблины без улыбок и синяков, исходные рыцари и беговые
позы; без чайника. [E — объём и свет](http://127.0.0.1:4180/?menu=E&motion=on)
использует отдельные фон/гоблинов, мягкую реакцию на мышь и свет. Старые варианты
сохранены. `?menu=A|B|C|D|E` открывает нужный вариант.

Новый арт D — только локальный preview вне Assets. Файлы
`TestResults/ui-entry-r1/menu-escape-v001.png`, `menu-escape-v002.png` и
`menu-escape-v003.png` игнорируются
Git и нужны для просмотра D / полной browser-проверки. В свежем checkout их нужно
восстановить отдельно; A/B/C работают с существующими ресурсами. [Brief, provenance
и точные prompts](menu-art-review.md). Production art_pipeline не запускался:
выбор финального кандидата пользователем ещё не получен. Для E также нужны
`TestResults/ui-entry-r1/menu-depth-background-v001.png` и
`menu-depth-foreground-v001.png`; [provenance и prompts слоёв](menu-depth-review.md).

Шрифты — Alegreya Sans Medium и PT Sans, palette из Art Direction §12.2.
Body — `fixture-character-agile-body.png` (CHAR-001) и `char-002-body.png`;
skill icons 001/003; thumbnails `field-001…010-background.png`.
Статические тексты сокращены из CD; это не источник для generated JSON.

## Повторяемые проверки

У D включён лёгкий motion preview: медленное смещение/приближение всей иллюстрации
(24 s в одну сторону, затем обратно) и семь слабых пылинок справа. Это не анимация
бега и не деформация персонажей. PNG не меняется, новые raster/video assets не нужны.
Кнопки/название неподвижны; pointer-events у декора отключены. Над макетом есть
«Оживление иллюстрации»; [статичный D](http://127.0.0.1:4180/?menu=D&motion=off).
Системный reduced-motion отключает эффект; скрытая вкладка приостанавливает CSS
animations, уход с Main Menu удаляет их вместе с декором. Это browser-only proposal,
не новый пункт игровых Settings и не готовая Unity-анимация.

E — отдельный послойный эксперимент. Слои имеют разные смещения и малый rotateY;
движение продолжается без мыши, pointer добавляет сглаженный небольшой сдвиг.
Текущий E принят пользователем 2026-09-28; [approval и hashes](menu-shepotka-review.md#visual-approval--2026-09-28).
Два выбранных слоя сохранены в `assets/` через Git LFS; E работает из этих
versioned review-копий, без зависимости от временных PNG. Неутверждённые варианты
D и старые генерации остаются локальными в TestResults; их отсутствие после
клонирования не мешает прямой ссылке `/?menu=E`. Полный исторический browser
verifier A–E по-прежнему требует локальные экспериментальные изображения D.
Справа бегущая Шепотка, в v002 — взрослее и со свёрнутыми картами вместо сумки,
только для этой иллюстрации: [preview и prompts](menu-shepotka-review.md).
Три выраженных широких луча качаются за героями с увеличенным размахом ±3°;
18 полупрозрачных пылинок среднего размера с мягкими краями проходят перед обоими
персонажами. Размер пыли 7.5–16.8 px до animated scale. Это самостоятельные
эффекты, не общая заливка и не осветление героев.
При выключении/reduced-motion остаётся статичная сборка; при скрытии/смене экрана
pointer loop отменяется. Кнопки и название не анимируются. Новые слои только
preview, v003 не перезаписан.

```powershell
node --check docs/implementation/proposals/ui-entry-r1/preview.js
node docs/implementation/proposals/ui-entry-r1/verify-preview.cjs
```

Второй скрипт требует Playwright; `PLAYWRIGHT_MODULE` принимает его установленный
путь. Используется **headless Chrome**, временный чистый профиль; закрытие browser
в `finally`. Личные вкладки и профили не используются, Edge не запускается.
Результат: `TestResults/ui-entry-r1/summary.json` и 34 captures (ignored).

Проверяются A/B/C/D/E, одинаковые действия/геометрия, прямые ссылки и сохранение
варианта после Back; motion timeline, покрытие кадра на пяти фазах, неподвижные
кнопки, выключение и reduced-motion; загрузка изображений/шрифтов, горизонтальное переполнение и viewport
bounds, locked/unpurchased confirm, мышь/Enter/Space, отдельное подтверждение,
Back с сохранённым персонажем, силуэты до покупки/раскрытие после, десять полей
без scroll, overflow 10 героев / 15 полей и неподвижность footer. Для E дополнительно:
реальная alpha, разные transforms слоёв, pointer response, границы света/кадра.
Ошибки
страницы/HTTP делают проверку неуспешной. Снимки дополнительно просматривает агент.
Это browser-only проверки; runtime tests и пользовательская приёмка отдельны.
