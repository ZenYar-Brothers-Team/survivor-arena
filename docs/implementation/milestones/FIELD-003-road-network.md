# FIELD-003 — перенос принятой сети дорог и доработка карты

Основание: [DECISION-0137](../../decisions/0137-field003-road-network-concept.md),
[принятая версия v4](../../prototypes/field003-roads/approved-v4/README.md).
Порядок ниже — зависимости этапов FIELD-003; он не возобновляет общий backlog
и не подменяет [execution order и состояние](../STATUS.md).

## Сохраняемая основа

Арена 200×200, высота опорного экрана H=10; основные дороги 10, тупики 8,
длина тупиков 20–40, округлый конец радиусом 7 (ревизия 2026-10-02: +20% с
округлением). Кольцо прижато к краю: 2 единицы травы до границы. Периметральное кольцо и редкая
связная внутренняя сеть со сглаженными поворотами и крупными обходами.
Расположение и связи меняются по seed. Редкость участков <2H важнее точных
15 тупиков/максимума 6H. Минимум 10, ориентир около 15, без верхнего лимита
книг. Одна книга с одним улучшением в каждом конце. Три покрытия: основная
дорога, разбитая дорога тупиков, трава FIELD-001. Игрок не выходит на траву.

Длинные периметральные маршруты известны и сохранены в принятом варианте;
их сокращение не должно возвращать сотоподобную сеть.

## R03-01 — генератор и обзор раскладок

Owners: IP-16/IP-23; Field/Presentation, authoring sources и `scripts/content/fields.py`.
Prerequisite: сохранённый профиль/эталонные координаты v4.

- Перенести генератор в C#, seeded RNG и domain validation; добавить authoring
  profile/DTO и генерацию catalog outputs через owning source.
- Получать общий граф, оси/поверхности дорог, ответвления и позиции книг.
  Геометрия, отображение и размещение наград используют один результат.
- Предусмотреть дешёвую проверку связности, границ, зазоров, циклов и метрики
  коротких участков с учётом книжных входов. Фиксировать причину отклонения.
- Ограничить работу генератора по бюджету; выбрать проверенный технический
  fallback до запуска забега. Не переносить буквально лимит 300 Python retries.
- Создать обзор seed с возможностью воспроизвести проблемную раскладку.

Gate: шесть эталонных координат читаются без потери геометрии; расширенная
серия не создаёт разорванных дорог или недоступных книг; минимум 10 проверяется
перед запуском, число <2H и время фиксируются. Невалидная геометрия не начинает run.
Строгий performance budget выбрать по замеру C#, Python timings его не заменяют.

## R03-02 — игрок и граница доступного пространства

Owner: IP-02, consumer IP-23. Prerequisite: R03-01.

- Объединить дорожные поверхности и округлые концы; строить границу с учётом
  контактного радиуса игрока. Применять один контракт к ходьбе, рывку и knockback.
- Выбрать допустимую безопасную точку старта на основной дороге; reload/restart
  используют полностью новый результат без старых коллайдеров/награды.
- Показать поле простыми цветами из принятой схемы для игрового просмотра.

Gate: игрок не выходит на траву, проходит стыки/повороты без зацепов, может
дойти до каждого конца и вернуться; pause/terminal/restart не оставляют старую
геометрию. Каждый подключённый герой проверяется с его фактическим контактным
радиусом; тест не предполагает единый радиус для всего roster.

## R03-03 — правила сущностей вне дорог

Owners: IP-02/IP-06/IP-20/IP-28/IP-29/IP-30; Bootstrap owns wiring.
Prerequisite: R03-02; необходим до полноценного боевого прогона.

Решение пользователя 2026-10-02: сохранить текущие правила всех сущностей
и наград. Враги/снаряды/Путники не ограничиваются дорогами, их спавн и
телепорты не корректируются ради доступности. XP/зелья/Traveler Books на траве
могут быть недоступными; существующее исчезновение/очистка сохраняются.
Нельзя включать grass blocker в obstacle clearance для размещения Путников.

Gate: дорожная граница влияет только на Player layer; обычный дроп не
переносится к дороге и не получает новый lifetime. Новые книги тупиков
размещаются в центрах концов и имеют доступ из основной сети.

## R03-04 — книги ответвлений

Owners: IP-28/IP-30, consumer IP-23; draft lifecycle IP-07/IP-11.
Prerequisite: R03-01…03.

- Разместить одну книгу в каждом округлом конце; награда ровно один выбор
  улучшения. Обычный Traveler reward не менять вместе с field pickup.
- Переиспользовать contact collect, общую draft queue и pause, однократное
  расходование, корректное завершение/смерть/restart. Не выдавать XP/level.
- По разрешению пользователя «как сейчас работает» книги появляются при
  сборке забега, сохраняют PICKUP-002 visual/contact/lifetime (сейчас null,
  без expiry), EmptyBookReward=50 и BookUpgradeReward=20 из MetaEconomy.
  Только число улучшений переопределено profile.bookUpgradeCount=1.
  Нового content ID нет: это тот же Book с явным override на экземпляре.

Gate: на каждой позиции один pickup; collect создаёт один запрос, повтор
не даёт вторую награду; пауза и конец run обрабатываются как у общего Book
lifecycle; все reward значения ссылаются на принятые definitions.

## R03-05 — игровой просмотр структуры

Prerequisite: R03-01…04. Текущие волны/BOSS-003/MIDBOSS-003 дают исходную нагрузку.

Проверить разные раскладки и героев: уклонение на дороге, риск захода за книгой,
видимость выхода, дистанции между решениями, длинные периметральные пробеги.
Сначала менять расстановку выходов/длины/зазоры, затем при необходимости волны.
Равномернее распределять выходы на кольцо можно без увеличения числа мелких петель.

Gate: получить конкретные наблюдения и выбрать следующую числовую ревизию;
точные 15 книг или cap 6H не являются критерием приёмки.

## R03-06 — покрытия, кромка и окружение

Owners: IP-12A/IP-23. Prerequisite: геометрия после R03-05.

Подготовить основную дорогу, более разбитые тупики, повторно использовать
траву FIELD-001. Сначала один gameplay-scale участок с перекрёстком и тупиком,
затем весь набор. Согласовать читаемую непроходимую кромку; заборы/камни и
дорожные посты не добавляют collider автоматически и не сужают принятые проходы.
Пакет/генерацию/импорт/проверки выполняет AI по art pipeline, визуальный выбор — пользователь.

Gate: рисунок дороги/тупика читается в бою, кромка совпадает с ограничением
движения, переходы не создают ложных проходов; gameplay-scale review пройден.
Миниатюру менять только если новый вид перестал соответствовать прежней.

## R03-07 — полный забег и завершение пакета

Prerequisite: R03-01…06. Обязательные scoped checks выбирать по WORKFLOW §9;
Unity запускать только по smoke-check safety procedure.

Проверить обычные волны, mid-boss/final boss, Путников, книги, смерть/победу,
паузы, restart и выбор другого поля. Генерация контента, art pipeline и
`check_project.py` проверяют конкретный изменённый scope; evidence сохраняется
отдельно, текущий статус/remaining acceptance — только STATUS.

Gate: обязательные автоматические checks и полный ручной забег новой FIELD-003
с evidence; числовая/визуальная приёмка не выводится из исторических результатов.
