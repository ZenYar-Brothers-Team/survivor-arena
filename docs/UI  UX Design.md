\# UI / UX Design

\#\# Статус

Approved.

> Стартовый набор, unlocks и Путники FIELD-001 утверждены пользователем 2026-09-22: [DECISION-0050](decisions/0050-starting-content-and-unlocks.md). Численные TBD и production data/art gates сохраняются.


Этот таб задаёт функциональный дизайн интерфейсов Survival Arena. Цель — использовать простые, привычные и дешёвые в реализации UI-паттерны без сложных нестандартных экранов и анимаций.

Главный принцип:

\> Игрок должен быстро понимать текущее состояние забега, свой билд и пути к сетам, а интерфейс не должен отвлекать от движения и боя.

Визуальный стиль интерфейса определяется отдельно через \`Art Direction v2\` и \`Art Production\`. Здесь фиксируется прежде всего структура, информация и поведение.

Уточнение 2026-09-28 ([DECISION-0083](decisions/0083-player-ui-layout-and-dev-boundary.md)):
утверждены visual language, набор действий и переходы. Временная раскладка
реализованного UI не является эталоном размеров, расположения и объёма текста.
Чистовая композиция проектируется отдельно на реальном контенте.

\---

\# 1\. Общие принципы

\- Интерфейс должен быть стандартным и понятным без обучения.  
\- Во время обычного боя игрок не должен постоянно взаимодействовать с UI.  
\- Основное активное UI-взаимодействие во время run — level-up draft, Book draft и pause/build screen.  
\- HUD показывает только информацию, которая нужна постоянно.  
\- Подробности билда и рецептов сетов доступны на паузе и в draft.  
\- Не вводить отдельные сложные drag-and-drop, radial-menu или nested-menu механики.  
\- Для первой версии ориентироваться на PC: клавиатура \+ мышь.  
\- Управление персонажем остаётся только движением; ручного aim через UI нет.  
\- Controller support можно добавить позже без изменения базовой структуры экранов.

\# 4\. Character Select

Экран показывает разблокированных и заблокированных playable characters.

Композиция entry R1: слева прокручиваемая сетка героев, справа крупный просмотр
и короткие сведения; footer с Back и отдельным подтверждением не прокручивается.
Нажатие закрытой карточки открывает только силуэт и «?», но не меняет допустимого
персонажа забега. Пока просматривается закрытый герой, подтверждение отключено.

\#\# Для выбранного персонажа показывать

\- для первой версии использовать crop/variant имеющегося body sprite; отдельный portrait генерировать только если такой вариант выглядит плохо;  
\- имя;  
\- starting active skill;  
\- основные отличия характеристик;  
\- короткое текстовое описание gameplay-роли.

Не нужно показывать весь внутренний набор параметров.

Показывать только значимые отклонения от baseline; полный набор точных внутренних характеристик на этом экране не нужен.

Baseline задаётся отдельными явными данными и не выбирается из первого или текущего персонажа. Данные персонажа содержат упорядоченный список отображаемых особенностей: автор контента явно выбирает, какие отличия показать, без автоматического процентного порога. Числовые отличия должны соответствовать характеристикам персонажа и baseline. Пустой список не дополняется автоматически. Это правило представления, оно не меняет gameplay stats. См. [DECISION-0026](decisions/0026-character-selection-baseline.md).

Например:

\`\`\`text  
HP: \+30%  
Move Speed: \-10%  
Starting Skill: Heavenly Strike  
\`\`\`

\#\# Locked character

Показывать:  
\- одноцветный силуэт body без деталей внешности, и в карточке, и в крупном просмотре;
\- «?» вместо имени; больше никаких сведений до получения героя.

Имя, роль, стартовое умение, характеристики, бонусы и условие разблокировки
не показываются ни в карточке, ни в крупном просмотре, ни в footer выбора героя.

По [DECISION-0087](decisions/0087-character-silhouettes-and-field-grid.md), пока
персонаж не получен (в том числе условие выполнено, но покупка ещё не сделана),
цветной body не раскрывается. После получения показывается исходный sprite.

\#\# Actions

\- выбрать персонажа;  
\- подтвердить и перейти к Field Select;  
\- Back.

\# 5\. Field Select

Для каждого разблокированного поля показывать:

\- название;  
\- thumbnail или простое изображение;  
\- locked/unlocked state.

Сложность на карточке поля не показывается (DECISION-0118); значение difficulty остаётся в данных поля.

Не нужно заранее показывать полный список врагов, точные wave timings или boss stats.

По [DECISION-0087](decisions/0087-character-silhouettes-and-field-grid.md) выбор
поля — компактная сетка без большой правой панели и без текстовых описаний
окружения (плетни, огороды, бочки и т. п.). Десять полей помещаются на одном экране
в 1280×720 и 1920×1080; при будущем расширении каталога скроллится только сетка,
а footer остаётся видимым. Клик/Enter/Space открывает просмотр карточки, Start Run
остаётся отдельным подтверждением. Причина блокировки выбранного поля — короткая
строка под сеткой; изменение presentation не удаляет description из content data.

\#\# Locked field

Показывать условие unlock. Закрытое поле не раскрывает thumbnail и название:
изображение сильно размыто, вместо названия — «?»; сложность и условие видны.

\#\# Actions

\- выбрать field;  
\- Start Run;  
\- Back.

\# 6\. Run HUD

HUD должен быть компактным и не перекрывать центр игрового поля.

По [DECISION-0086](decisions/0086-ui-review-density-and-inspection.md) HUD не
показывает wave information и текстовые инструкции WASD/стрелок/Settings/Pause.
Кнопки паузы в игровом HUD нет; пауза доступна через Escape / Space / ПКМ
по DECISION-0084, bindings есть в Settings. Timer по центру. При 1280×720 его окно компактнее, размеры слотов
active/passive/acquired sets и длина XP-блока примерно на 40% меньше макета до
review; все типы слотов одинакового размера. Масштаб 1920×1080 сохраняется.
Числа уровней остаются читаемыми; HP у героя не масштабируется этим правилом.

\#\# Постоянно видимые элементы

\#\#\# Top center  
\- timer оставшегося игрового времени \`15:00 → 00:00\` для 15-минутного забега; на паузе не меняется, после нуля не уходит в отрицательное значение ([DECISION-0069](decisions/0069-field001-feedback-tuning.md)).

\#\#\# Top / boss area  
\- boss HP bar только когда final boss активен; только имя, без чисел HP. Mid-boss показывает свой HP bar над головой ([DECISION-0110](decisions/0110-health-bars-no-numbers-midboss-overhead.md)).

\#\#\# Bottom / lower area  
\- XP bar;  
\- current level.

\#\#\# Возле персонажа
Основной player HP bar привязан к персонажу и следует за ним, с отступом от
силуэта. Постоянного дубликата в нижней или верхней экранной панели нет.
Current/max HP также доступны в Pause / Build. Boss/Traveler bars сохраняют
свои отдельные роли. Точное смещение и размер проверяются в игровой сцене.

Замедленный противник получает голубую ледяную фактуру внутри силуэта и компактную
полоску оставшегося времени под ногами. Это относится к обычным врагам, боссам и
Путникам с body art. На паузе полоска не уменьшается; по окончании эффекта оба
элемента исчезают. Основание: [DECISION-0108](decisions/0108-slow-status-look-preview.md).

\#\#\# Development controls
Скорость 1×/2×/3×/5× доступна только в Editor/Development Build, в свёрнутом
DEV drawer по DECISION-0005, и не входит в player HUD или Settings. Release UI
не показывает controls и не принимает их intents; обычный run идёт на 1×.
Development lifecycle скорости сохраняет Running/pause/end/reset из
[DECISION-0140](decisions/0140-run-speed-controls.md), уточнённого DECISION-0083.

\#\#\# Build icons  
Показывать компактно:  
\- до 6 active skill icons \+ level;  
\- до 6 passive icons \+ level;  
\- полученные set icons.

Иконки маленькие; подробное описание открывается только в Pause / Build screen.

\#\# Optional lightweight indicators

\- количество доступных reroll;  
\- количество доступных banish.

Их можно показывать только во время draft, а не постоянно в HUD.

\# 7\. Level-up Draft

При level-up игра ставится на паузу.

Открывается стандартный экран с \*\*3 карточками выбора\*\*.

До показа неполного драфта свободные позиции дозаполняются доступными сетами с неудачной проверкой шанса — равновероятно и без повторов, по GDD. Неудачный бросок сам по себе не означает пустую позицию, пока такие сеты доступны. Это же правило отображения применяется к Book Draft.

\#\# Каждая карточка содержит

\- icon;  
\- название;  
\- тип: «Активное», «Пассивное» или «Сет»;
\- current level → new level, если это upgrade;  
\- краткое описание того, что изменится после выбора;  
\- set-related information, если вариант участвует в рецептах.

Не показывать длинное полное описание механики, если его можно заменить короткой конкретной формулировкой.

Шапка карточки компактная, как в макете R2: слева иконка, справа тип и уровень;
название ниже, по левому краю. Тип — крупный цветной текст без овальной плашки
или обводки (21 px в 720p / 24 px в 1080p). Иконка — 88/112 px,
подпись уровня — 18/21 px соответственно. Активное — приглушённый голубой,
пассивное — зелёный, сет — золотой; цвет не заменяет текстовую подпись.

Основной текст отвечает на вопрос «что даст этот выбор». Вместо постоянного
поля длинного описания — список связанных рецептов и компоненты выбранного
рецепта по §8 / DECISION-0086. Существенные эффекты нельзя скрывать простым
обрезанием текста. Точные вторичные коэффициенты заменяются качественной
формулировкой: «+1 рикошет. Повторный удар слабее».

Урон ([DECISION-0085](decisions/0085-ui-damage-percent-presentation.md)):
абсолютный базовый урон умения не показывать ни в карточке, ни в подробностях.
Прибавки к урону показывать в процентах, например «+50% урона». Для нового
умения — краткое действие и другие существенные параметры, без базового числа.
Точный процент сохранённого урона и отбрасывания повторного удара не показывать;
он не является прибавкой. HP, количество снарядов, секунды и уровни компонентов сохраняют
свои единицы. Это не изменение gameplay damage или stacking.

Все player-facing проценты округлять до целого (половины от нуля), без
отрицательного нуля. Непроцентные дробные числа, например регенерация 0.35/с,
не округлять до целого. Ускорение использования считать по обратному времени
перезарядки, а не менять знак процента её уменьшения: `100 × (t_old / t_new − 1)`,
где оба времени — положительные секунды. Например, 2 → 1.5 с = +33%.
Время перезарядки в секундах нигде не показывается, в том числе у нового умения; игрок видит
только относительное изменение «Скорость использования ±N%» (пользователь, 2026-09-30).
Для изменившегося бонуса скорости `b` (доля, `b > −1`) относительный прирост —
`100 × ((1 + b_new) / (1 + b_old) − 1)`: 0 → 0.33 = +33%.
Если сокращение lifetime только компенсирует рост скорости полёта при прежней
дальности, не показывать его как ухудшение «Время действия −…%»; оставить
изменение скорости полёта. У Броска камня 10 → 11.5 world units/s = +15%,
дальность 5 world units сохраняется. Реальное изменение длительности эффекта
не переименовывать в скорость использования и не скрывать этим правилом.

Заголовок обычного draft — «Выбери улучшение», Book — «Книга странника».
Номера текущего/следующего уровня забега из шапки убрать. При наличии очереди
показывать только «Ещё улучшений: N», где N — число ожидающих выборов без
текущего (`N ≥ 1`); без очереди подпись скрыта. Уровень самой карточки и
компонентов рецепта сохраняется.

Пример:

\`\`\`text  
Rock Throw  
Lv. 3 → 4

\+1 ricochet  
Subsequent hits are weaker.
\`\`\`

\#\# Actions

\- выбрать одну из 3 карточек;  
\- Reroll;  
\- Banish.

По [DECISION-0112](decisions/0112-draft-one-click-selection.md) клик по карточке
сразу получает вариант. Клавиатура карточки драфта не выбирает и не
переключает просмотр (DECISION-0118): карточки не фокусируются с клавиатуры.
Наведение показывает связанные сеты в нижней области; после ухода курсора остаётся информация о
последней просмотренной карточке. Изначально просматривается первая доступная.
Смена рецепта/scroll не подтверждают выбор. Enter/Space принадлежат
сфокусированному control (не карточке) и не вызывают одновременно pause/selection.
Смена предложений сбрасывает просмотр; при пустом пуле выбора нет.

\#\#\# Reroll  
Кнопка пересобирает текущие предложения по правилам GDD и заново выполняет set checks. Banish сохраняет результаты проверок остальных сетов текущего запроса (DECISION-0022).

Рядом показывать оставшееся количество.

\#\#\# Banish  
Простой вариант реализации:  
1\. нажать кнопку \`Banish\`;  
2\. навести курсор на карточку для просмотра;
3\. нажать карточку для исключения;
4\. вариант исключается из pool до конца run, draft обновляется.

В режиме Banish клик по карточке исключает вариант вместо получения. Cancel возвращает обычный выбор без расхода. Reroll в этом режиме неактивен. После успешного исключения, смены предложений или закрытия draft режим сбрасывается. Показывать остатки и причины недоступности controls.

Не вводить отдельный сложный banish screen.

\# 8\. Set information in Draft

Это обязательная часть UI, потому что построение сетов является одной из центральных целей run.

Игрок не должен запоминать все 20 рецептов самостоятельно.

\#\# Для active/passive option

В карточке показывать только количество связанных meta-открытых сетов,
которые ещё не получены и рецепт которых всё ещё можно выполнить:

\`\`\`text  
Сеты: 6
\`\`\`

Названия и прогресс не дублировать в карточке. В списке сначала рецепты,
которые завершит выбор, затем ближайшие к завершению.

Недостижимые рецепты не входят ни в число, ни в список связанных сетов.
Причины недостижимости — прежние по DECISION-0073: нужных свободных слотов
меньше, чем недостающих компонентов соответствующего типа, либо отсутствующий
компонент нельзя получить. Уже взятый компонент ниже порога доступен через
улучшения. Готовый, но не полученный сет остаётся. Упущенные видны только
в своём разделе Pause, а не среди вариантов развития в Draft / Book.

\#\# Detailed set info

Для последней просмотренной карточки под вариантами показывать ограниченную область:
слева список связанных сетов (иконка + имя + числовой прогресс), справа краткий основной
эффект сета и уровни компонентов выбранного рецепта. Эффект — тот же короткий
текст, что в справке Pause, без технических коэффициентов и длинного описания.
Список прокручивается при 6–10 рецептах; последовательной
карусели со стрелками нет. Выбор рецепта не сбрасывает scroll. При нуле
связанных сетов область скрыта без сдвига карточек и действий.
Число слева — уже полученные компоненты / общее число компонентов, независимо
от их уровней, без прибавления ещё не выбранного улучшения. Поэтому 3/3 может
сосуществовать со статусом «В процессе» или «Завершит рецепт», а не «Рецепт готов».
Справа ✓ означает наличие компонента, ○ — отсутствие. Достигнутый текущий
порог уровня выделяется зелёным с подписью «Уровень набран»; один лишь preview
следующего уровня не делает строку зелёной. Например:

\`\`\`text  
Cold Orbit — 3/4

✓ Orbit Blades  
✓ Ice Shards  
✓ Light Boots  
○ Hardened Skin  
\`\`\`

Для текущего draft option нужный component визуально выделяется.

\#\# Important states

Если выбор текущей карточки:

\#\#\# Завершает рецепт  
Показывать яркое, но простое сообщение:

\`Завершит рецепт\`

Это означает завершение recipe requirements. Сам set всё равно активируется
только после последующего появления и подтверждения set-card по правилам GDD.
Это правило документации, не поясняющий абзац под карточками.

\#\#\# Продвигает рецепт  
Показывать:

\`В процессе\` и числовой прогресс, например \`2/4 → 3/4\`.

\#\#\# Уже не нужен для recipe progression  
Не акцентировать set information сильнее обычного.

Если все требования уже выполнены — «Рецепт готов». «Получен» используется
только после выдачи сета; готовность рецепта и получение не смешиваются.

\#\# Component levels

Если рецепт требует минимального уровня компонента, progress считается по фактически выполненному threshold.

То есть UI должен отличать:  
\- компонент имеется, но ещё недостаточного уровня;  
\- threshold выполнен.

Простой вариант визуализации:

\`◐ Rock Throw Lv.2 / required Lv.4\`

и после выполнения:

\`✓ Rock Throw Lv.4\`

\#\# Goal

Игрок должен прямо во время draft понимать:

\- какие sets доступны через этот вариант;  
\- насколько близок каждый set;  
\- завершит ли этот выбор recipe;  
\- что ещё нужно собрать.

\# 9\. Set card in Draft

Когда completed recipe проходит \`setDraftChance\` и set попадает в draft, он показывается как отдельная карточка.

Set-card должна визуально отличаться от Active/Passive card, но использовать ту же общую структуру.

\#\# Показывать

\- set icon;  
\- set name;  
\- label \`SET\`;  
\- короткое описание эффекта;  
\- числовую готовность рецепта; компоненты — в общей нижней области по §8;
\- отметку, что set не занимает active/passive slot.

Пример:

\`\`\`text  
SET — Cold Orbit

Orbit effects apply Slow.  
Bonus damage against slowed enemies.

FREE SET SLOT  
\`\`\`

Никакого отдельного экрана подтверждения после выбора не требуется.

Наведение на set-card открывает просмотр. Клик сразу
получает set, draft закрывается по обычным правилам очереди.

\# 10\. Pause / Build Screen

Manual pause открывает один простой full-screen overlay.

Игра полностью остановлена.

Композиция по DECISION-0086: персонаж/stats и 6+6 компактных слотов слева
примерно на треть ширины; область изображения персонажа немного увеличена.
Справа — сеты в порядке «Получены», рецепты, «Упущены», с общей вертикальной
прокруткой всех трёх разделов. Рецепты — три колонки при 1920×1080 и две при
1280×720. Между названием компонента и уровнем меньше пустоты.
Все 12 слотов и общий footer
Resume / Settings / Quit видны при 1280×720 и 1920×1080 без прокрутки экрана.

\#\# Показывать

\#\#\# Character  
\- имя;  
\- current HP / max HP;  
\- несколько основных текущих stats.

Скорость — процент от общего default baseline CHARACTER-BASELINE-001, а не
от старта выбранного героя: `round(100 × currentMovementSpeed / baselineMovementSpeed)`.
Обе величины в world units/s; current конечна и ≥0, baseline конечна и >0;
вывод — целый неотрицательный процент. При baseline=3 скорость 3 даёт 100%,
3,6 даёт 120%, в том числе у быстрого героя с начала run. Неверный baseline
не заменяется скоростью выбранного героя; это ошибка данных.

\#\#\# Active Skills  
Сетка до 6 icons:  
\- icon;  
\- name;  
\- level.

\#\#\# Passives  
Сетка до 6 icons:  
\- icon;  
\- name;  
\- level.

\#\#\# Acquired Sets  

Компактный раздел «Получены» справа: только иконка и название, как у упущенных,
но с золотым вертикальным разделителем и своим заголовком. При отсутствии
полученных сетов раздел скрыт. Описание доступно по нажатию, не занимает место
у каждой записи постоянно.

\#\#\# Set Progress  
Список всех meta-открытых ещё не полученных sets, которые можно собрать в этом
забеге, в том числе без единого взятого компонента.

Для каждого:

\`\`\`text  
Cold Orbit — 3/4  
✓ Orbit Blades  
✓ Ice Shards  
✓ Light Boots  
○ Hardened Skin  
\`\`\`

Числитель в Pause и в draft inspector одинаков — число взятых компонентов, независимо от их
уровня; достижение требуемых уровней отражает статус («В процессе» / «Рецепт готов»).

Достижимый рецепт без взятых компонентов показывается с `0/N` и статусом
«Не начат», где N — число компонентов рецепта. Состав и требуемые уровни видны
сразу, краткий эффект доступен по нажатию, чтобы игрок мог заранее выбрать цель.
Наличие progress не является условием видимости. Meta-закрытые сеты скрыты;
длинный список целиком доступен через общую прокрутку правой области.

Упущенные (по прежним правилам DECISION-0073) — последними в отдельном разделе
«Упущены», отделённом вертикальной чертой: только иконка и название каждой
записи, без компонентов и больших recipe cards. Иконки и шрифт немного крупнее
промежуточного R2 ради читаемости, не уменьшать их при росте списка. Раздел
содержит все упущенные meta-доступные сеты, включая ещё не начатые рецепты.
Полученные сеты остаются отдельной группой; остальные используют короткие статусы §8.

Нажатие любого сета в правой области (получен / рецепт / упущен) открывает
небольшую всплывающую справку: иконка, название, статус и краткий эффект,
без детальных коэффициентов. Keyboard activation равнозначна клику.
Справка не меняет layout, не перекрывает footer и не выбирает/выдаёт сет.
Крестик, клик снаружи, Escape или ПКМ закрывают её без второго действия
и без снятия паузы. Явное закрытие возвращает фокус на исходный сет.
При scroll, смене экрана или размера справка закрывается.

\- Resume;  
\- Settings;  
\- Quit Run.

\# 11\. Traveler UI

\#\# On-screen

Отдельный большой UI panel не нужен.

Для всех Travelers показывать простой HP bar над сущностью, независимо от их роли.

\#\# Off-screen  
Используется уже заданная GDD стрелка у края экрана:  
\- показывает направление;  
\- исчезает, когда Traveler снова видим;  
\- исчезает после ухода/смерти Traveler.

Уточнение [DECISION-0109](decisions/0109-traveler-offscreen-pointer.md): стрелка «ездит» по рамке
экрана близко к краю (небольшой отступ) и повёрнута точно к Путнику; на каждого невидимого Путника —
своя стрелка, совпадающие раздвигаются вдоль рамки. На стрелке нет HP и таймера; под ней
приглушённая подпись «Путник» без конкретной роли. Стрелка заметная, подпись не притягивает
внимание. Видимый Путник показывает только свой HP bar.

\#\# Optional timer  
Для первой версии \*\*не показывать точный countdown до ухода\*\*, если gameplay не докажет, что он необходим.

Можно использовать простой visual warning ближе к моменту ухода позже.

\# 12\. Traveler Book Draft

Подбор Book:  
\- ставит игру на паузу;  
\- открывает отдельный draft из 3 предложений;  
\- не повышает level.

UI максимально переиспользует обычный Level-up Draft.

Различия:  
\- заголовок \`Traveler Book\` / эквивалент;  
\- визуальный accent;  
\- нет level-up presentation.

Set-information на карточках работает так же, как в обычном draft. Книга использует обычный pool и общий остаток reroll/banish.

После дозаполнения сетами 1–2 варианта показываются с неактивными пустыми позициями. Если предложений нет уже при подборе Книги, пустой draft не открывается: игрок сразу видит прибавку валюты. Обычный пустой level-up валюты не даёт. Рядом с текущим draft видно только количество ещё ожидающих выборов, без номера уровня и origin следующего; terminal result закрывает draft и отменяет ожидающие выборы.

\# 13\. Boss UI

Когда final boss появляется:

\- сверху появляется boss HP bar;  
\- показывается имя boss;  
\- обычный HUD остаётся видимым.

Не делать отдельную boss intro cutscene для MVP.

Допустимо короткое сообщение:

\`BOSS INCOMING\`

или имя boss при появлении.

Верхняя полоска — только у final boss, с именем и без чисел HP. Каждый живой mid-boss показывает
собственный HP bar над головой, пока он на экране, без имени и чисел; указателя за краем у него нет
([DECISION-0110](decisions/0110-health-bars-no-numbers-midboss-overhead.md)). Числа здоровья не выводятся ни на одной полоске.

Поскольку убийство final boss не требуется для победы, timer остаётся главным индикатором конца run.

\# 14\. Notifications

Использовать короткие стандартные notifications.

Нужные события:

\- \`LEVEL UP\`;  
\- \`SET RECIPE COMPLETED\`;  
\- \`SET ACQUIRED\`;  
\- \`TRAVELER APPEARED\`;  
\- \`TRAVELER ESCAPED\`;  
\- \`BOSS INCOMING\`;  
\- \`NEW CHARACTER UNLOCKED\`;  
\- \`NEW FIELD UNLOCKED\`.

Правила:  
\- короткий текст;  
\- не блокирует gameplay, кроме draft;  
\- исчезает автоматически;  
\- несколько notifications не должны закрывать центр экрана одновременно.

Вывод по [DECISION-0107](decisions/0107-hostile-damage-notifications-midboss-coins.md): коды выше — типы
событий, а не отображаемый текст. Один канал — плашка в правом верхнем углу в палитре и шрифтах
интерфейса: строка события («Новый уровень», «Сет получен», «Приближается босс»…) и строка объекта
(имя сета/Путника/босса/открытия или «Уровень N»). Текст берётся из одной таблицы строк — место
будущей локализации. Подряд идущие level-up склеиваются в последний уровень; несколько открытий
одного результата показываются одной плашкой «Новые открытия» с числом.

\# 16\. Run Results

Один простой summary screen. Quit Run также открывает Results без дополнительного
подтверждения, с подписью «Забег прерван»; обрабатываемая ошибка — «Забег остановлен».
Награда одинакова: 5 × число уровней, полученных после стартового L1, плюс 20 за успешное улучшение из Книги
и 50 за каждую пустую при подборе Книгу (DECISION-0090). Показывать отдельно награду
за уровень, Книги и итог из сохранённого receipt данного RunId, не начислять повторно.
Справа сначала новые открытия (сеты, активные/пассивные умения, персонажи, карты),
затем собранные сеты. Формат открытия: изображение, название, тип. Общая прокрутка
только этой коллекции; исход, факты, награда и действия остаются видимыми в 1080p/720p.
При ошибке записи показывать «Не удалось сохранить результат» и Retry Save;
Retry run, новый run и покупки недоступны до успешной записи pending результата.
Ошибки загрузки/backup recovery/reset — по [DECISION-0037](decisions/0037-meta-economy-and-persistence.md).

\#\# Показывать

\- Victory / Defeat;  
\- survival time;  
\- final level;  
\- kills;  
\- meta currency earned;  
\- acquired sets;  
\- unlocked content, если появился новый unlock.

Дополнительно, если данные уже доступны без дополнительной сложной реализации:  
\- top 3 skills by damage.

Не строить сложный analytics screen для MVP.

\#\# Actions

\- Retry;  
\- Main Menu.

Retry немедленно запускает новый run с теми же character и field без возврата к selection и без дополнительных подтверждений.

\# 17\. Meta Progression

Первая версия должна быть простой.

\#\# Main screen

Показывать:  
\- текущую meta currency;  
\- доступные permanent upgrades;  
\- доступные unlock purchases.

Permanent upgrades отображаются компактными карточками: перед названием простой
сгенерированный значок характеристики 32×32, без рамки и без увеличения высоты
карточки. Набор META-003…014 утверждён 2026-09-29; иконки сетов не переиспользуются.
Порядок типов: урон, скорость действий, размер предметов; здоровье, снижение урона,
регенерация, эффективность лечения; скорость движения, радиус подбора, опыт;
перебросы и исключения в самом конце. Переключение бонусов обновляет карточки
без перестроения списка и скачка позиции прокрутки.
Три колонки на 1080p, две на 720p; список прокручивается отдельно от шапки и кнопок.
Выбор открытого героя — миниатюры под большим портретом в собственной прокручиваемой
области, выбранная миниатюра выделена золотой рамкой. Выпадающего списка нет.
Карточки показывают улучшения только выбранного открытого персонажа;
глобальный блок отменён поручением 2026-09-29. Расширение типов и платный возврат —
[DECISION-0091](decisions/0091-personal-meta-upgrades-and-refund.md); утверждённые
цены/пределы — в Content Design. Кнопка возврата сбрасывает только выбранного героя
за 1000 монет, с подтверждением и показом возврата/комиссии/итогового баланса.
Если баланс плюс возврат меньше 1000, кнопка недоступна с причиной; равенство
разрешает сброс с итогом 0. Комиссия удерживается в том числе из возврата.
Покупки только вне run. На пределе уровня,
при недостатке валюты или pending сохранении Buy отключён с явной причиной.
Ошибка покупки не списывает валюту; новые upgrades действуют со следующего run.

Над списком карточек — галочка «Disable permanent upgrades (play from scratch;
no refund, levels kept)» ([DECISION-0064](decisions/0064-disable-permanent-upgrades.md)).
Видна только на экране Meta Progression (не в DEV-панели); меняется только вне run
и при сохранённом профиле, иначе неактивна. Выбор сохраняется в профиле. Пока галочка
стоит: все upgrade-карточки помечены `inactive`, в сводке строка «Permanent upgrades
are disabled: runs start without meta bonuses», экран выбора персонажа показывает
«Permanent bonuses: disabled in Meta progression». Покупки остаются доступными и
накапливают уровни, которые начнут действовать после снятия галочки. Unlocks не
затрагиваются. Ошибка записи оставляет прежнее значение и показывает сообщение.

Каждая карточка:  
\- icon;  
\- name;  
\- current level;  
\- effect;  
\- price;  
\- Buy button.

\#\# Unlocks

Characters/fields/content, открываемые за currency, могут использовать тот же простой card pattern.

Achievement-based unlocks показывают условие вместо price.

По [DECISION-0092](decisions/0092-unlocks-collection-ui.md) вкладка содержит весь
каталог, включая начальные открытия. Фильтры: все/персонажи/карты/умения/сеты
и все состояния/не открыто/можно купить/открыто. Умения объединяют active/passive.
Три колонки на 1080p, две на 720p, одна прокрутка; фильтры, монеты, счётчик и
возврат остаются снаружи. Пустой результат фильтра имеет короткое пояснение.
Состояния фильтра показывают количество записей; счётчик открытого относится
к выбранной категории, чтобы стартовая открытая группа не воспринималась как
весь доступный каталог. «?» закрытого персонажа показывается вместо имени,
без второго вопросика поверх силуэта. Изображения доступны при первом входе
в Meta прямо из главного меню, без предварительного выбора героя.
Неоткрытые персонажи остаются силуэтами с «?»; сеты сохраняют названия
и изображения. Неоткрытая карта показывает сильно размытый thumbnail и «?» вместо названия
(в Unlocks и в Field Select), пока не открыта. Отменённое замечание о скрытии
всего контента не применяется.

Не строить сложное skill tree, если оно не требуется GDD.

\- Recipe-completing;  
\- Set card.

Не создавать сложную систему rarity colors, если gameplay её не требует.

\# 20\. UI implementation principles

Чтобы UI было просто реализовывать:

\- переиспользовать один \`DraftCard\` component для Active / Passive / Set / Book Draft;  
\- переиспользовать один простой \`ContentCard\` для Character / Field / Meta Unlocks, где возможно;  
\- использовать стандартные grid/list layouts;  
\- не делать draggable UI;  
\- не делать complex animated navigation;  
\- не делать уникальный screen transition для каждого экрана;  
\- использовать обычные buttons, panels, tooltips и progress bars;  
\- подробности показывать tooltip/detail panel вместо перегруженных основных карточек;  
\- текст и layout должны работать до финального UI art.

Функциональная версия на простых shapes/placeholders подтверждает state/intent
contracts. Перед чистовой версией отдельно пересматриваются информационная
иерархия, layout, размеры и плотность текста; затем применяется утверждённый стиль.
Переиспользование компонентов не обязывает сохранять геометрию прототипа.

За окнами Meta/«Развитие», «Открытия» и Results — полноэкранный непрозрачный
тёмно-сливовый фон, без просвечивающей тестовой сцены. Игровые overlays сохраняют
игровой фон. В коллекции доступны иллюстрации всех десяти карт; готовый artwork
не означает готовность или доступность карты для запуска.

Следующие элементы для MVP можно делать без отдельной generated art:  
\- buttons;  
\- panels;  
\- HP/XP bars;  
\- boss bar;  
\- draft card backgrounds;  
\- progress indicators;  
\- tooltips;  
\- locked overlay;  
\- selected/hover states;

Утверждённый общий visual language — **«Полевой фолиант»** из
[Art Direction §12.2](art/ART_DIRECTION.md#122-визуальный-язык-ui--полевой-фолиант)
и [DECISION-0081](decisions/0081-field-folio-ui-visual-language.md). Это современная
функциональная структура в классическом сказочном оформлении: матовый
угольно-сливовый каркас, кожа, тёплый пергамент, ржавчина, приглушённая зелень и
дозированное золото. Главными цветными объектами остаются персонажи, thumbnails и
production-иконки; отдельные raster-рамки и декоративные фоны не обязательны.

Экранное применение:

\- Main Menu — поле с тёмной сливовой виньеткой и компактная колонка действий;
\- Character Select — крупный body crop, роль, starting skill и 2–4 отличия;
\- Field Select — thumbnail как главный visual, difficulty и lock condition;
\- HUD — наиболее сдержанные панели, HP green, XP azure, boss coral/burgundy;
\- Draft — эталонные три карточки с type marker, effect и recipe block;
\- Pause / Build — компактные character/stats/build слева, расширенные recipes справа;
\- Results — outcome, run facts, rewards и unlocks с явной иерархией;
\- Meta — permanent upgrades и unlocks визуально разделены;
\- Settings — нейтральные стандартные controls в общей теме без декоративной
  имитации механических рычагов.

Целевой вертикальный visual slice для утверждения реализации:
`HUD → Level-up Draft → Pause / Build`. Он обязан сначала доказать тему,
типографику, состояния, читаемость production-иконок и layout при `1920×1080` и
`1280×720`; только затем язык переносится на остальные экраны.

Review использует настоящий игровой фон, production-иконки и реальные тексты,
player HP возле героя и полную Pause-композицию с Resume/Settings/Quit.
Fixture long-text/empty-icon captures проверяют устойчивость, но не заменяют
эту демонстрацию. Скорость и прочий DEV исключены из player-facing кадров.

\# 23\. Resolved review decisions

Следующие решения подтверждены:

1\. Character Select сначала использует crop/variant существующего body sprite. Отдельные portraits генерируются только если результат выглядит недостаточно хорошо.  
2\. На Character Select показываются только явно выбранные в данных персонажа modifiers относительно отдельно заданного baseline, без автоматического порога значимости и полного списка точных внутренних stats (DECISION-0026).
3\. Pause / Build показывает все meta-открытые достижимые sets, включая `0/N`
без взятых компонентов; все упущенные
meta-доступные сеты — отдельным компактным разделом (DECISION-0073/0086).
4\. HP bar показывается для всех Travelers.  
5\. Retry немедленно перезапускает run с теми же character и field без дополнительных кликов.
6\. Общий UI visual language — «Полевой фолиант» с умеренной декоративностью и
современной функциональной структурой (DECISION-0081).
7\. Кнопки скорости — development-only; временная геометрия интерфейса не
утверждена вместе со стилем (DECISION-0083).
8\. Основной player HP bar находится возле персонажа и следует за ним;
отдельная верхняя/нижняя панель для здоровья игрока не используется (DECISION-0083).

9\. HUD density, краткие формулировки, inspect/confirm, компактные missed и
скорость от общего baseline уточнены DECISION-0086. Композиционная проработка —
[layout R2](implementation/proposals/2026-09-28-ui-layout-r2.md); макет не является
приёмкой Unity runtime.


## Стартовая прогрессия — DECISION-0050

Утверждено пользователем 2026-09-22; [Content Design](Content_design.md#starting-content-0050)
и [DECISION-0050](decisions/0050-starting-content-and-unlocks.md) задают состав и условия.

- Character Select: на новом профиле доступна Клёпка; для Бугра показывать
  «Пройдите Деревенскую окраину», затем цену 100 и обычное состояние покупки.
  Прочие character unlocks берутся из карточек CD.
- Level-up, Book и reroll не показывают locked skills/passives/sets. В подсказках
  рецептов при draft и Pause Build показывать прогресс только meta-открытых сетов;
  не направлять игрока к недоступным компонентам. Banish и component thresholds
  по-прежнему участвуют в recipe eligibility.
- Сет, рецепт которого уже нельзя выполнить (не хватает свободных слотов нужного типа
  или отсутствующий компонент больше не может выпасть — banish/locked), показывается
  последним в разделе «Упущенные сеты» (MISSED SETS) Pause Build и DEV-списка рецептов ([DECISION-0073](decisions/0073-playtest-2026-09-27-sets-boss-fields-balance.md)).
  В Draft / Book такой сет полностью исключён из связанного списка и счётчика
  по DECISION-0086; на доступность самих draft options этот display filter не влияет.
- В существующем Meta Progression → Unlocks показывать закрытые active/passive/set
  карточки с названием и понятным условием «Пройдите …». Группировать по полю,
  открывающему пакет; не добавлять отдельный экран или skill tree. Выполнение
  условия бесплатно, Buy для этих карточек отсутствует.
- Results после успешного сохранения перечисляет только новые открытия текущего
  результата по категориям. Можно показать пакет компактно с раскрытием полного
  списка; новые открытия доступны со следующего забега, включая Retry FIELD-001.
  Ошибка сохранения сохраняет pending-состояние; повтор Retry Save не повторяет
  уведомление. Восстановление/миграция старого профиля не выдаёт повторный Results.
- Field Select не показывает постоянный лимит «10/10/5» у первого поля: состав
  принадлежит профилю и расширяется. Повторный заход использует текущие открытия.
- Число слотов HUD/Pause остаётся 6 active / 6 passive. Изменение состава
  само по себе не меняет visual style; это не запрещает отдельно согласованную
  переработку размеров и расположения UI по DECISION-0083.
